## 1. for 循环：括号里到底是什么

C / C++ / Java 这类语言，`for` 括号里是三段式，用**两个分号**切成三块（注意：是分号，不是逗号）：

```c
for (初始化; 条件; 更新)
```

| 位置 | 官方叫法 | 作用 | 执行时机 |
|---|---|---|---|
| 第 1 段 | 初始化（init） | 定义/赋值循环变量 | **只在进入循环前执行 1 次** |
| 第 2 段 | 条件（condition） | 判断是否继续循环 | **每轮循环开始前都判断 1 次** |
| 第 3 段 | 更新（update/step） | 改变循环变量 | **每轮循环体结束后执行 1 次** |

执行顺序（务必记牢）：

```
初始化 → [判断条件 → 执行循环体 → 执行更新] → 判断条件 → 执行循环体 → 执行更新 → ... → 条件为假，退出
```

> ⚠️ 顺序陷阱：**"先判断再执行"**，所以条件不成立时循环体一次都不执行。
> ⚠️ 第三段是在循环体**之后**执行的，不是之前。

任何一段都可以留空，但两个分号**不能省**：

```c
for (;;)        { /* 死循环，等价于 while(1) */ }
for (int i = 0; ; i++) { ... }   // 省条件 = 永真
for (; i < 10; i++)    { ... }   // 省初始化
```

## 2. 单 for 双变量 vs 双层 for 网格

这是两个**完全不同**的东西，只是都能"同时看到 x 和 y"。

### 2.1 ① 单 for 同时控制 x、y（同步配对）

**适用场景**：x 和 y 同步变化、一一配对，比如画对角线、做对称、双指针相向走。

```c
// x: 0→4 递增，y: 10→6 递减，一共只跑 5 轮
for (int x = 0, y = 10; x < 5; x++, y--) {
    printf("x=%d, y=%d\n", x, y);
}
```

特点：
- **只有一层循环**，总轮次由同一个条件控制；
- 初始化区用逗号写多个声明（`int x = 0, y = 10`）；
- 更新区用逗号写多个表达式（`x++, y--`）；
- x、y 是**同一节奏的两个变量**，代表"一条线上同步跑的两个点"。

条件里也可以同时判断两个：

```c
for (int x = 0, y = 100; x < 10 && y > 50; x++, y -= 5) { ... }
```

### 2.2 ② 双层 for 网格（x 列、y 行）

**适用场景**：二维表格、图片像素、地图格子、矩阵——要遍历**每一个 (x, y) 组合**。

```c
for (int y = 0; y < height; y++) {        // 外层：行
    for (int x = 0; x < width; x++) {    // 内层：列
        // 处理像素 (x, y)
    }
}
```

特点：
- 外层走一步，内层要把**一整行全部跑完**；
- 总执行次数 = `height × width`（笛卡尔积，所有组合）；
- 内层循环的次数是外层次数的倍数关系。

### 2.3 一句话区分

| | 单 for 双变量 | 双层 for |
|---|---|---|
| 循环层数 | 1 层 | 2 层 |
| 总执行次数 | 一组，n 次 | h × w 次 |
| x、y 关系 | 同步变化，一对一 | 所有组合（全排列遍历） |
| 典型场景 | 对角线、双指针、对称 | 图像、矩阵、网格地图 |

> 记忆口诀：**单 for 双变量是"并肩走"，双层 for 是"格子铺满"。**

## 3. for 的初始化区能定义多个变量吗

✅ **C / C++ / Java：可以，但必须是同一种类型。**

```c
// ✅ 合法：同类型，逗号分隔
for (int x = 0, y = 10; x < 5; x++, y--) { ... }

// ❌ 非法：类型不同不能写在同一条声明里
for (int x = 0, double y = 1.5; ...) { ... }   // 编译错误
```

如果需要不同类型，只能把变量提到 for 外面先定义：

```c
int x = 0;
double y = 1.5;
for (; x < 5; x++, y += 0.5) { ... }
```

### 语法原理

`for(A; B; C)` 中的 A 是一个**声明或表达式**，里面的逗号是**逗号运算符/声明分隔符**，不是语句分隔符。
`int x = 0, y = 10` 本质是"一条声明语句里声明两个同类型变量"，所以类型必须一致。

> ❌ Python 没有三段式 for，不存在"初始化区写多个变量"这回事（见下一节）。

### 补充坑：for 里声明的变量作用域

```c
for (int i = 0; i < 10; i++) { ... }
printf("%d", i);   // ❌ 报错！i 只在 for 内部有效（C99 起）
```

## 4. Python / JS / Go / Rust 的 for 长什么样

### 4.1 Python —— 没有三段式 for，只有"遍历型"

Python 的 for 是 **for-each**，遍历可迭代对象，不是"条件循环"：

```python
for i in range(5):
    print(i)
```

#### Python 实现「单 for 双变量同步」

方式 1：`zip`（最推荐，语义最清晰）

```python
for x, y in zip(range(0, 5), range(10, 5, -1)):
    print(x, y)
```

方式 2：手动推导

```python
for i in range(5):
    x, y = i, 10 - i
    print(x, y)
```

#### Python 实现「双层 for 网格」

```python
for y in range(height):
    for x in range(width):
        print(f"pixel ({x}, {y})")
```

#### 想模拟 C 的三段式？用 while

```python
x, y = 0, 10
while x < 5:
    print(x, y)
    x += 1
    y -= 1
```

### 4.2 JavaScript —— 和 C 几乎一样

```js
for (let x = 0, y = 10; x < 5; x++, y--) {
    console.log(x, y);
}
```

### 4.3 Go —— 三段式，但注意 Go 没有 while

```go
for x, y := 0, 10; x < 5; x, y = x+1, y-1 {
    fmt.Println(x, y)
}
```

Go 的 `for` 一身兼任 while：

```go
for x < 5 { }        // 等价 while
for { }              // 等价 while(1) 死循环
for i := range arr { } // 等价 for-each
```

⚠️ Go 的更新段**不支持逗号表达式**，必须写成多重赋值 `x, y = x+1, y-1`。

### 4.4 Rust —— for 是迭代器，双变量用 zip

```rust
// 单变量
for x in 0..5 {
    println!("{}", x);
}

// 双变量同步（zip）
for (x, y) in (0..5).zip((0..10).rev()) {
    println!("{} {}", x, y);
}

// 网格
for y in 0..height {
    for x in 0..width {
        println!("({}, {})", x, y);
    }
}
```

### 4.5 Lua —— 数值 for 是"起点, 终点, 步长"

```lua
-- 原生只有数值 for，没有三段式
for x = 0, 4 do
    local y = 10 - x
    print(x, y)
end

-- 带步长
for i = 10, 1, -1 do end
```

### 4.6 横向对比表

| 语言 | 三段式 for | 一次多变量 | 双变量同步推荐写法 |
|---|---|---|---|
| C | ✅ | ✅（同类型） | `for(int x=0,y=10;...;x++,y--)` |
| C++ | ✅ | ✅（同类型；也可 `for(auto [x,y] : ...)`） | 同上 / 结构化绑定 |
| Java | ✅ | ✅（同类型） | 同上 |
| JavaScript | ✅ | ✅ | 同上 |
| Go | ✅ | ❌ 逗号表达式不支持 | `x, y = x+1, y-1` |
| Rust | ❌ 迭代器式 | 用 `zip` 或元组 | `(0..5).zip(...)` |
| Python | ❌ 遍历式 | 用 `zip` | `for x,y in zip(a,b)` |
| Lua | 起点/终点/步长 | ❌ | 循环体内自己算 |

## 5. 伸缩性数组成员（柔性数组 FAM）

> 官方中文名：**伸缩性数组成员 / 柔性数组成员**；英文 **Flexible Array Member (FAM)**；C99 标准引入。

### 5.1 定义

结构体的**最后一个成员**，写成 `type name[]`，**不指定长度**，运行时靠 `malloc` 额外分配：

```c
struct Msg {
    int len;        // 前面必须有至少一个具名成员
    char buf[];     // ✅ 柔性数组，必须是最后一个
};
```

### 5.2 五个核心特点

1. **不算进 `sizeof`！**
   ```c
   printf("%zu\n", sizeof(struct Msg));   // 只等于 sizeof(int)
   ```
   柔性数组本身**不占结构体空间**，它只是一个"位置标记"。

2. **只能放最后，且前面不能空**：
   - ❌ 不能放中间、不能放开头；
   - ❌ 不能是结构体唯一的成员。

3. **不能定义栈上变量，只能用 `malloc`**：
   ```c
   int n = 100;
   struct Msg *p = malloc(sizeof(struct Msg) + n * sizeof(char));  // 头 + 数组
   p->len = n;
   p->buf[0] = 'a';   // ✅ 这样才合法
   ```
   ```c
   struct Msg m;      // ❌ 合法编译但 buf 没有空间
   m.buf[0] = 'a';    // ❌ 未定义行为！
   ```

4. **标准 C 中不能作为其他结构体的成员、不能做数组元素**（GCC 扩展允许）。

5. **`char buf[0]`（零长数组）是 GCC 扩展，不是标准 C**；标准写法是 `buf[]`。

### 5.3 完整可运行示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Packet {
    int size;
    unsigned char data[];
};

int main(void) {
    int payload_len = 16;
    struct Packet *pkt = malloc(sizeof(struct Packet) + payload_len);
    if (!pkt) return 1;

    pkt->size = payload_len;
    for (int i = 0; i < payload_len; i++)
        pkt->data[i] = (unsigned char)i;

    printf("header size = %zu\n", sizeof(struct Packet));   // 4（假设 int 4 字节）
    free(pkt);   // ✅ 一次 free 释放全部
    return 0;
}
```

### 5.4 常见坑

| 坑 | 说明 |
|---|---|
| 栈上直接用 | `struct Packet p; p.data[0] = 1;` → 没有分配空间，UB |
| 直接浅拷贝 | `struct B b = *a;` 只复制头部，数组部分丢失 |
| 忘记按需扩容 | realloc 时要重新算 `sizeof(struct X) + 新长度` |
| 和 VLA 混淆 | VLA 是局部变长数组（长度运行时定，但固定）；FAM 是结构体尾部占位，靠 malloc 追加 |

## 6. 柔性数组 vs 普通指针成员

这是 FAM 最容易被误用的对照：

```c
// 版本 A：柔性数组（一块连续内存）
struct MsgA {
    int len;
    char buf[];
};

// 版本 B：普通 char*（两块独立内存）
struct MsgB {
    int len;
    char *buf;
};
```

内存布局对比：

```
版本 A（FAM，连续）：
┌────────┬────────────────────────────┐
│  len   │ buf[0] buf[1] ... buf[n-1] │  ← 全部一块 malloc
└────────┴────────────────────────────┘
         ↑ 结构体头    ↑ 追加的数组空间（同一块内存）

版本 B（指针，分离）：
┌────────┬────────┐          ┌─────────────────────┐
│  len   │  buf*  │ ───────► │ heap 上的另一块内存 │
└────────┴────────┘          └─────────────────────┘
         结构体一块               数组另一块（第二次 malloc）
```

| 对比项 | 柔性数组 A | 指针成员 B |
|---|---|---|
| malloc 次数 | 1 次 | 2 次 |
| free 次数 | 1 次 | 2 次（漏一次就泄漏） |
| 内存连续性 | ✅ 连续，cache 友好 | ❌ 两块，可能分散 |
| 可拷贝性 | 需按长度整体 memcpy | 浅拷贝会共享指针，易 double free |
| 典型用途 | 网络包、协议头、内核结构 | 一般动态字符串/缓冲区 |

> 口诀：**FAM 一次分配一次释放，连续紧凑；指针成员两次分配两次释放，容易泄漏。**

## 7. `'\0'` 到底占不占字节

### 7.1 结论

- `'\0'` 就是 ASCII 值为 **0** 的 char，**本身就是 1 个字节**：
  ```c
  char c = '\0';    // 占 1 字节，值为 0
  ```
- 关键不是"占不占"，而是**"需不需要预留它的位置"**：

| 用途 | 是否要留 `\0` 的位置 |
|---|---|
| 当 **C 字符串**用（交给 `printf("%s")`、`strlen`、`strcpy`） | ✅ **必须留 1 字节** |
| 当 **二进制缓冲区**用（网络包、原始字节流，长度自己记） | ❌ 不需要 |

### 7.2 三种"个数"的区别（超高频混淆）

```c
char s[] = "abc";
```

| 概念 | 值 | 说明 |
|---|---|---|
| `sizeof(s)` | **4** | 数组真实占用字节数，**包含 `\0`** |
| `strlen(s)` | **3** | 有效字符数，**不含 `\0`** |
| 分配时要写的大小 | **4** | 想存 `"abc"` 就必须留 4 字节 |

> ❌ 错误认知：`strlen` 和 `sizeof` 一样 → **错，差 1（前提是合法 C 字符串）**。

### 7.3 结合柔性数组的分配

```c
struct Packet { int len; char data[]; };

// 情况 A：存二进制 3 字节 → 分配 3
struct Packet *p1 = malloc(sizeof(struct Packet) + 3);
p1->len = 3;
p1->data[0]='a'; p1->data[1]='b'; p1->data[2]='c';
// ✔ 没有 '\0'，靠 len 记长度，完全正确

// 情况 B：存 C 字符串 "abc" → 必须分配 4（多留 1 给 '\0'）
struct Packet *p2 = malloc(sizeof(struct Packet) + 4);
p2->len = 3;
strcpy(p2->data, "abc");   // strcpy 会写进第 4 个字节的 '\0'
```

> ⚠️ 情况 B 只分配 3 字节 + `strcpy` = **越界写**，缓冲区溢出的经典源头。

## 8. 占位（FAM）vs `'\0'` vs 对齐填充 padding

三个东西经常被混为一谈，本质完全不同：

| 对比项 | 柔性数组成员 `data[]` | `'\0'` | 结构体对齐填充 padding |
|---|---|---|---|
| 是什么 | **编译期的位置标记/占位符** | **运行时的真实数据字节** | 编译器为了让齐插入的空白 |
| 占不占内存 | ❌ **不占**（不进 sizeof） | ✅ 占 **1 字节** | ✅ 占（可能 1~7 字节） |
| 有没有值 | 没有值（不是 0） | 值 = 0 | 未定义（编译器随意填） |
| 能否访问 | 通过名字访问"后面那块内存" | 可以读写 | ❌ 不应访问（无意义） |
| 作用 | 允许申请结构体尾部的扩展空间 | 标记 C 字符串结束 | 保证成员地址对齐，提升访问效率 |

### 一句话区分

- **FAM**：占"位置"，不占字节 —— 它只是"门票"，让你能用 `p->data[i]` 访问后面 malloc 来的内存。
- **`'\0'`**：占"字节"，是数据 —— 内存里实实在在的 1 个 0。
- **padding**：占"字节"，但不是数据 —— 对齐用的空隙，不能拿来存东西。

### 对齐填充示例

```c
struct S {
    char c;     // 1 字节
    // 这里通常插 3 字节 padding（假设 int 需 4 字节对齐）
    int  i;     // 4 字节
};
// sizeof(struct S) = 8，而不是 5！
```

> 这也是"**结构体大小 ≠ 成员大小之和**"的原因，和 FAM 的"不进 sizeof"是两件不同的怪事。

## 9. 字符数组初始化的 4 种写法（最关键的一节）

这是今天最容易出错的地方，必须一张表记死。

### 9.1 四种写法与结果

```c
// ① 固定长度，填不满 → 剩余自动补 0
char chs2[4] = {'t','o','m'};
// 内存: 't' 'o' 'm' '\0'   sizeof = 4   ✅ 有 '\0'

// ② 省略长度 + 字符列表 → 长度=元素个数，不加 '\0'
char chs3[] = {'j','a','c','k'};
// 内存: 'j' 'a' 'c' 'k'    sizeof = 4   ❌ 没有 '\0'

// ③ 省略长度 + 字符串字面量 → 自动多塞一个 '\0'
char chs4[] = "jack";
// 内存: 'j' 'a' 'c' 'k' '\0'   sizeof = 5   ✅ 有 '\0'

// ④ 固定长度 + 字符串字面量
char chs5[5] = "jack";
// 内存: 'j' 'a' 'c' 'k' '\0'   sizeof = 5   ✅ 有 '\0'
```

### 9.2 关键规则（务必区分）

**规则 1：`arr[N] = {值列表}`，列表元素数 < N**
→ 剩下的元素**全部自动初始化为 0**，于是尾部自带 `\0`。

```c
char a[10] = {'a','b'};        // a[2]..a[9] 全是 0
```

**规则 2：`arr[N] = {值列表}`，列表元素数 == N**
→ 刚好填满，**不会额外补 `\0`**。

```c
char b[4] = {'j','a','c','k'};  // 4 个位置全占满，没有 '\0'
```

**规则 3：`arr[] = {值列表}`**
→ 数组长度 = 元素个数，**不补 `\0`**。

```c
char c[] = {'j','a','c','k'};   // 长度 4，没有 '\0'
```

**规则 4：只有"字符串字面量"，才会自动追加 `\0`**

```c
char d[] = "jack";              // 长度 5，含 '\0'（特例魔法）
char e[] = {"jack"};            // 同上，花括号包一个字符串也合法
```

### 9.3 一张表总结

| 写法 | 合法 | sizeof | 有 `\0` | `%s` 输出是否安全 |
|---|---|---|---|---|
| `char a[4] = {'t','o','m'};` | ✅ | 4 | ✅（自动补） | ✅ 安全 |
| `char a[4] = {'j','a','c','k'};` | ✅ | 4 | ❌ | ❌ 越界读 |
| `char a[] = {'j','a','c','k'};` | ✅ | 4 | ❌ | ❌ 越界读 |
| `char a[] = "jack";` | ✅ | 5 | ✅ | ✅ 安全 |
| `char a[] = {"jack"};` | ✅ | 5 | ✅ | ✅ 安全 |
| `char a[] = {'j','a','c','k', '\0'};` | ✅ | 5 | ✅ | ✅ 安全（手动补） |
| `char a[5] = {'j','a','c','k'};` | ✅ | 5 | ✅（第5个自动0） | ✅ 安全 |
| `char a[] = {jack};` | ❌ | — | — | 编译报错 |

> **填不满，空位归零；**
> **刚填满，一毛不拔；**
> **双引号，白送一个零；**
> **单引号裸列，啥都不送。**

## 10. `{jack}` 为什么是错的，`{"jack"}` 为什么合法

### 10.1 `{jack}` —— 编译错误

```c
char chs[] = {jack};    // ❌ 编译报错：undeclared identifier 'jack'
```

原因：`jack` **没有引号**，编译器把它当成**标识符（变量名）**，而不是字符/字符串。
你没有定义过名为 `jack` 的变量 → 直接报错。

正确写法只有两种：

```c
char chs[] = {'j','a','c','k'};   // 单引号，单个字符（无 '\0'）
char chs[] = "jack";              // 双引号，字符串（有 '\0'）
```

### 10.2 `{"jack"}` —— 合法，等价于 `"jack"`

```c
char chs[] = {"jack"};    // ✅ 合法
```

C 标准允许用**花括号包一个字符串字面量**作为字符数组的初始化器，结果和 `= "jack"` 完全一样：

```c
char chs[] = {"jack"};
// 等价于 char chs[] = {'j','a','c','k','\0'};
// sizeof = 5，含 '\0'，%s 安全
```

### 10.3 ⚠️ 核心区别：花括号里装的是"一个字符串"还是"一堆字符"

| 写法 | 花括号里是什么 | 是否带 `\0` |
|---|---|---|
| `{"jack"}` | **一个字符串**（双引号） | ✅ 带 |
| `{'j','a','c','k'}` | **四个独立字符**（单引号） | ❌ 不带 |

**这是唯一的分水岭：双引号 → 自带 `\0`；单引号 → 一个字符，各算各的。**

### 10.4 中文引号坑

```c
char s[] = "jack";     // ✅ 英文直引号
char s[] = “jack”;     // ❌ 中文弯引号 “ ” → 编译错误
```

复制粘贴代码时务必确认引号是英文的 `"` 和 `'`。

## 11. `%s` 是怎么"找"`'\0'` 的：栈？堆？全局区？

### 11.1 核心答案（先背这句）

> **`printf("%s")` 不知道数组有多长、不知道数组边界，也完全不关心内存在栈、堆还是全局区。
> 它只做一件事：从你给的首地址开始，逐字节往后读，读到字节值 == 0 才停。**

### 11.2 它到底怎么实现（伪代码）

```c
void print_str(const char *p) {
    while (*p != '\0') {   // 解引用当前地址，判断是不是 0
        putchar(*p);
        p = p + 1;         // 地址 +1，跳到下一个字节
    }
}
```

就两句：**判断 → 打印 → 指针自增**。没有任何边界检查、没有长度参数。

### 11.3 "后面的内存"属于哪个区？取决于数组在哪分配

| 数组存放位置 | 例子 | `%s` 越界后会往哪读 |
|---|---|---|
| **栈**（局部变量） | 函数内 `char chs[] = {...}` | 往栈上相邻内存读（别的局部变量、栈残留垃圾、栈帧数据） |
| **堆**（malloc） | `char *p = malloc(4)` | 往堆块后面读（可能读进堆管理结构，可能踩坏别人数据） |
| **全局/静态区** | 函数外 `char chs[] = {...}` | 往全局区后面读（可能读到别的全局变量、常量区） |

**规则不变：数组在哪，它就从哪往后扫。** 不是"专门去栈里找"。

### 11.4 三种可能的结果（未定义行为 UB）

1. **运气好**：往后不远碰到某个 0 → 多输出一串乱码，程序正常结束；
2. **运气差**：一路扫到**未映射的内存页** → `Segmentation fault`（Linux/macOS）或访问冲突（Windows），程序崩溃；
3. **更隐蔽**：踩到相邻变量，把别人的数据当字符串打印出来，泄露信息。

> ⚠️ 每次运行结果都可能不同，因为栈上"垃圾"是随机残留的。**这属于未定义行为（UB），不是"有时能跑就算对"。**

### 11.5 内存示意（局部数组场景）

```c
void f(void) {
    char chs[] = {'j','a','c','k'};   // 栈上
    printf("%s\n", chs);
}
```

```
栈（向低地址增长，这里按读的方向画）
┌──────┬──────┬──────┬──────┬───────────────────────────────┐
│ 'j'  │ 'a'  │ 'c'  │ 'k'  │ ← 数组边界到此结束            │
└──────┴──────┴──────┴──────┴───────────────────────────────┘
                              ↓ 继续往后（越界）
              ┌──────┬──────┬──────┬──────┬──────┬──────┐
              │ 0x?? │ 0x?? │ 0x?? │ 0x00 │ ...  │ ...  │
              └──────┴──────┴──────┴──────┴──────┴──────┘
                 ↑ 别的变量/栈垃圾（内容随机）  ↑ 碰巧是 0，停止
```

### 11.6 安全写法对照

```c
// ❌ 危险：没有 '\0'
char bad[] = {'j','a','c','k'};
printf("%s\n", bad);

// ✅ 安全 1：手动补
char ok1[] = {'j','a','c','k', '\0'};
printf("%s\n", ok1);

// ✅ 安全 2：用字面量
char ok2[] = "jack";
printf("%s\n", ok2);

// ✅ 安全 3：有长度上限的写法
printf("%.*s\n", (int)sizeof(bad), bad);   // 最多打印 4 个字符，不越界
```

> ⚠️ 优先级更高的安全习惯：**别裸写 `%s` 打印没有终止符的缓冲区**，尤其是来自外部输入的数据。

## 12. 二维数组怎么算行数和列数

### 12.1 公式（仅适用于**静态定义的**二维数组）

```c
int arr[M][N];
```

| 目标 | 表达式 |
|---|---|
| 总字节数 | `sizeof(arr)` |
| **一行占多少字节** | `sizeof(arr[0])` |
| **单元素字节** | `sizeof(arr[0][0])` |
| **行数 rows** | `sizeof(arr) / sizeof(arr[0])` |
| **列数 cols** | `sizeof(arr[0]) / sizeof(arr[0][0])` |

理解要点：
- `arr[0]` → 第 0 行，类型是 `int[N]`（一个一维数组），所以 `sizeof(arr[0])` = 一整行的字节；
- `arr[0][0]` → 单个元素，`sizeof` = 一个 int 的字节。

### 12.2 套到今天的例子

```c
int num3[][3] = {
    {1,2,3},
};
```

假设 `int` = 4 字节：
- `sizeof(num3[0])` = 3 × 4 = **12**（一行）
- `sizeof(num3)` = 1 × 12 = **12**（只有一行）
- `rows = 12 / 12 = 1`
- `cols = 12 / 4 = 3`

### 12.3 遍历（标准双层 for）

```c
#include <stdio.h>

int main(void) {
    int num3[][3] = {
        {1, 2, 3},
        {4},          // 第二行：4 0 0
    };

    int rows = (int)(sizeof(num3) / sizeof(num3[0]));
    int cols = (int)(sizeof(num3[0]) / sizeof(num3[0][0]));

    printf("rows=%d, cols=%d\n", rows, cols);

    for (int i = 0; i < rows; i++) {       // i：行
        for (int j = 0; j < cols; j++) {   // j：列
            printf("%d ", num3[i][j]);
        }
        printf("\n");
    }
    return 0;
}
```

输出：

```
rows=2, cols=3
1 2 3
4 0 0
```

> 注意 `{4}` 这一行：给 1 个元素，剩下的自动补 0 —— 和字符数组"填不满自动归零"是同一条规则。

### 12.4 ⚠️ 三个必考的坑

**坑 1：这个算法只对"原生静态数组"有效**

```c
int **p;            // sizeof(p) = 8（指针大小），算不出任何行列！
int (*p)[3];        // sizeof(p) 也是指针大小
```

指针退化后，`sizeof` 只能得到**指针本身的字节数**，不是数组总大小。

**坑 2：二维数组当函数形参会退化**

```c
void func(int arr[][3]) {
    // ❌ sizeof(arr) 这里是指针大小（8），不是数组总字节
    // 算不出行数！
}
```

C 规定数组形参等价于指针，一维退化一层：
- `int a[]` → `int *a`（退化 1 层）
- `int a[][3]` → `int (*a)[3]`（退化 1 层，第二维保留）

所以**函数里传二维数组，必须把行数当参数一起传**：

```c
void func(int arr[][3], int rows) {
    for (int i = 0; i < rows; i++)
        for (int j = 0; j < 3; j++)
            printf("%d ", arr[i][j]);
}
```

**坑 3：第二维不能省略**

```c
int a[][3] = {...};   // ✅ 合法，第一维由编译器数
int a[3][]  = {...};  // ❌ 非法！第二维必须写死
```

原因：编译器要算出"一行多大"才能定位每个元素的行地址；
`a[i][j]` 的地址 = 起始地址 + `i * (行字节) + j * (元素字节)`，行大小必须已知。

### 12.5 二维数组的地址计算（理解这个就全通了）

```c
int a[3][4];
```

```
a[i][j] 的地址 = a 的起始地址 + (i * 4 + j) * sizeof(int)
                        └──── 把二维压平成一维的索引 ────┘
```

所以二维数组在内存里其实是**一维连续排布**，只是编译器按"每 4 个元素换一行"来解释。

> 顺带一提：`a`、`a[0]`、`&a[0][0]` 的**值相同（地址相同）**，但**类型不同**：
> - `a` → `int (*)[4]`（指向一整行的指针）
> - `a[0]` → `int *`（指向一个元素）
> - `&a[0][0]` → `int *`
> 类型不同导致 `+1` 跳的字节数不同：`a + 1` 跳一整行（16 字节），`a[0] + 1` 跳 4 字节。

## 13. 易错点总清单（背下来）

### 13.1 for 循环

- [ ] ❌ 以为 `for(A;B;C)` 用逗号分隔 → **是分号**
- [ ] ❌ 以为"先执行循环体再判断条件" → **先判断，条件假则一次都不执行**
- [ ] ❌ 以为更新段在循环体之前执行 → **在之后**
- [ ] ❌ `for(int x=0, double y=1; ...)` → **同一条声明里类型必须一致**
- [ ] ❌ `for(int i=...)` 之后在循环外使用 `i` → **C99 起作用域只在循环内**
- [ ] ❌ 把"单 for 双变量"当成"网格遍历" → **前者同步，后者是全组合**

### 13.2 柔性数组 FAM

- [ ] ❌ `struct X { char buf[]; int len; };` → **FAM 必须最后**
- [ ] ❌ `struct X { char buf[]; };` → **不能是唯一成员**
- [ ] ❌ `struct X x; x.buf[0] = 1;` → **必须 malloc，否则 UB**
- [ ] ❌ `sizeof(struct X)` 里算上数组 → **FAM 不进 sizeof**
- [ ] ❌ `= *a` 浅拷贝 → **数组部分不会自动复制**
- [ ] ❌ 把 `char buf[0]` 当标准写法 → **那是 GCC 扩展，标准是 `buf[]`**
- [ ] ❌ 把 FAM 和 VLA 混为一谈

### 13.3 `'\0'` 与占位

- [ ] ❌ `strlen` 等于 `sizeof` → **`sizeof` 含 `\0`，`strlen` 不含，差 1**
- [ ] ❌ `'\0'` 是"占位符不占字节" → **`'\0'` 就是 1 字节真实数据**
- [ ] ❌ FAM 的 `data[]` 当成"里面有个 0" → **它是位置标记，没有值**
- [ ] ❌ 把 padding 当成可写空间
- [ ] ❌ 二进制缓冲区多分配或不分配 `\0` 搞混

### 13.4 字符数组初始化

- [ ] ❌ `char a[] = {'j','a','c','k'};` 后用 `%s` → **没有 `\0`，越界读**
- [ ] ❌ 以为 `arr[N]` 一定会补 `\0` → **只有"填不满"才补**
- [ ] ❌ `char a[] = {jack};` → **编译报错，缺引号**
- [ ] ❌ 中文引号 `“jack”` → **编译报错**
- [ ] ❌ `{"jack"}` 和 `{'j','a','c','k'}` 当成一样 → **差一个 `\0`**

### 13.5 `%s` 与越界

- [ ] ❌ 以为 `%s` 会检查数组长度 → **不会，只认字节值 0**
- [ ] ❌ 以为没 `\0` 时"程序会自动去栈里找" → **它只是顺着地址往后读，数组在哪就往哪扫**
- [ ] ❌ "程序没崩就说明没问题" → **UB 的表现不稳定，属于潜在 bug**
- [ ] ❌ 对未终止缓冲区裸写 `printf("%s")`，尤其是外部输入

### 13.6 二维数组

- [ ] ❌ 函数里 `sizeof(arr)` 算行数 → **形参已退化为指针**
- [ ] ❌ `int a[3][]` → **第二维必须写死**
- [ ] ❌ `int **p` 用 sizeof 算行列 → **只是指针大小**
- [ ] ❌ 以为 `a + 1` 跳 1 个元素 → **跳一整行**
- [ ] ❌ `{4}` 这行只有 1 个值 → **其余自动补 0，不是"只剩 4"**
