## 1. 指针运算全家桶：`*p+1` / `*(p+1)` / `*p++` / `(*p)++` / `*(++p)`

### 1.1 前提

```c
int arr[] = {10, 20, 30};
int *p = arr;      // p 指向 arr[0]
```

```
地址 A     : 10   ← p
地址 A + 4 : 20
地址 A + 8 : 30
```

优先级：`*`（解引用） > `+`（算术）；`++`（后缀）高于 `*`；`++`（前缀）与 `*` 同级右结合。

### 1.2 三个"取值类"表达式

| 表达式 | 等价形式 | 运算过程 | 结果 | p 是否移动 |
|---|---|---|---|---|
| `*p + 1` | `(*p) + 1` | 先取 `*p`=10，再数值 +1 | **11** | ❌ 不动 |
| `*(p + 1)` | `*( (p+1) )` | 指针先走 1 个元素到 `arr[1]`，再解引用 | **20** | ❌ 不动 |
| `p + 1` | — | 指针加法，得到新地址 | **&arr[1]** | ❌ 不动（除非 `p = p+1`） |

> 分水岭一句话：
> **`*p + 1` 是"房子不动、房里数字+1"；`*(p+1)` 是"先搬到下一间房、再拿新房的数"。**

### 1.3 两个"自增类"表达式（高频考点，最容易翻车）

```c
*p++      // 后缀 ++ 优先级更高 → 等价 *(p++)
(*p)++    // 括号强制先解引用 → 等价 ((*p) + 1)，注意不是"取完再加1存回去"的完整描述
*(++p)    // 前缀 ++ 先执行 → 指针先走，再取值
```

#### `*p++`（后缀自增）
规则：**后缀 `++` 先返回旧值，再自增**。所以 `*(p++)` 的执行顺序是：
1. 记下 p 当前地址（临时保存）；
2. p 自增（指向下一个元素）；
3. 对**旧地址**解引用取值。

```c
int arr[] = {10, 20, 30};
int *p = arr;
printf("%d\n", *p++);   // 输出 10
// 执行完 p 已经指向 arr[1]（20）
```

#### `(*p)++`
1. 解引用拿到 `arr[0]` 的值 10；
2. 对**这个值所在的内存**做自增 → `arr[0]` 变成 11；
3. 表达式的结果是**旧值 10**（后缀语义）；
4. **p 不动**，仍指向 `arr[0]`。

```c
p = arr;
printf("%d\n", (*p)++);   // 输出 10，但此时 arr[0] == 11
printf("%d\n", arr[0]);   // 11
```

#### `*(++p)`
1. 前缀 `++` 先把 p 自增，指向 `arr[1]`；
2. 再对新地址解引用 → 20。

```c
p = arr;
printf("%d\n", *(++p));   // 输出 20，p 指向 arr[1]
```

### 1.4 五个表达式总表（背下来）

| 表达式 | 结果（arr={10,20,30}, p=arr） | arr 内容变化 | p 最终指向 |
|---|---|---|---|
| `p + 1` | `&arr[1]`（地址） | 无 | arr[0] |
| `*p + 1` | `11`（数值） | 无 | arr[0] |
| `*(p + 1)` | `20`（数值） | 无 | arr[0] |
| `*p++` | `10`（数值） | 无 | **arr[1]** |
| `(*p)++` | `10`（数值，旧值） | **arr[0] → 11** | arr[0]（不动） |
| `*(++p)` | `20`（数值） | 无 | **arr[1]** |

### 1.5 关键概念：指针加法的"步长"

```c
p + 1
```

**不是地址 +1 字节，而是地址 + `sizeof(*p 指向的类型)`**：

| 指针类型 | `p + 1` 地址实际增加 |
|---|---|
| `char *` | 1 字节 |
| `int *` | 4 字节 |
| `double *` | 8 字节 |
| `Point *`（假设 Point 8 字节） | 8 字节 |

> 这就是"指针类型为什么重要"的根本原因：**类型决定步长**（下一节 `void*` 也是这个道理）。

### 1.6 口诀

> `*p+1`：原地取值，数字加一
> `*(p+1)`：先走一步，再取值
> `*p++`：先取值，指针后搬家
> `(*p)++`：原地数字变大，房子不动
> `*(++p)`：先搬家，再取值

## 2. 数组指针与二维偏移：`*(scores+i)+j` vs `*scores+i*col+j`

### 2.1 前提：`scores` 是「数组指针」，不是二级指针

```c
int arr[2][3] = {{1,2,3}, {4,5,6}};
int (*scores)[3] = arr;    // 指向"一整行 int[3]"的指针
int col = 3;
```

关键：`scores` 的类型是 `int (*)[col]`，**它一步跳一整行**。

### 2.2 写法 A：`*(scores + i) + j`（标准的"分层访问"）

```
scores + i
  scores 是行指针 int(*)[col] → +i 跳过 i 整行（i*col 个 int）
  结果类型：仍是 int(*)[col]
    ↓
*(scores + i)
  对行指针解引用 → 得到"这一行"，类型 int[col]
  在表达式中数组自动退化为 int*（本行首元素地址）
  结果类型：int*
    ↓
*(scores + i) + j
  int* + 整数 → 指针偏移，往后跳 j 个 int
  结果类型：int*
```

**语义**：先跳到第 i 行 → 再在该行内部向右走 j 个元素。
这就是编译器翻译 `&scores[i][j]` 的原生形式。

### 2.3 写法 B：`*scores + i*col + j`（"拍扁成一维"）

```
*scores
  直接对原始 scores 解引用 → 固定拿到第 0 行
  退化成 int*（永远指向 arr[0][0]）
    ↓
i*col + j
  纯算术：跳过前面 i 行全部元素，再加本行偏移 j
    ↓
*scores + (i*col + j)
  int* + 整数 → 一次性向后跳 i*col+j 个 int
```

**语义**：钉死在第 0 行开头，把整个二维数组当成一根长条，直接数 `i*col+j` 个元素。

### 2.4 两者的对比

| 对比项 | `*(scores+i)+j` | `*scores+i*col+j` |
|---|---|---|
| 起点 | 跟随行走，动态跳到第 i 行 | 永远固定在第 0 行开头 |
| 第一步的步长 | **一整行**（`col` 个元素） | 没有"行"的概念，按单个元素跳 |
| 中间类型 | `int (*)[col]` → `int *` | 全程 `int *` |
| 是否依赖内存连续 | 不依赖（行可以分散） | **强依赖：整块连续** |
| 语义 | 行优先二维访问 | 手动把二维拍平成一维 |
| 典型场景 | `scores[i][j]` 的底层原型，规范写法 | 柔性数组整块分配、手写 offset |
| `int **scores` 能用吗 | ✅ 可以（`*(scores+i)` 拿到第 i 行指针） | ❌ **绝对不行，会越界崩溃** |

### 2.5 ⚠️ 核心大坑

在**内存连续的静态二维数组**上，两种写法最终落到同一个地址，**运行时结果相同**。
但：

1. **语义、类型流转完全不同**，不能混为一谈；
2. 一旦换成 `int **scores`（每行单独 malloc、行与行不连续），写法 B 直接越界；
3. `col` 传错 → 整个下标错乱，直接越界（没有任何边界检查兜底）。

### 2.6 和 1.1 的关联

为什么 `*p + 1` 是"数值 +1"，而 `*scores + k` 是"指针偏移"？

> **看解引用之后是什么类型！**
> - `*p`（`p` 是 `int *`）→ 结果 `int`（**数值**）→ 后面 `+1` 是算术加法
> - `*scores`（`scores` 是 `int(*)[col]`）→ 结果 `int[col]` → 退化为 `int *`（**指针**）→ 后面 `+k` 是**指针偏移**

一句话：**解引用出数值 → 数字加；解引用出指针 → 指针跳。**

## 3. `&(*(*scores+i*col+j))` 逐层拆解

原式：

```c
&( * ( *scores + i * col + j ) )
```

### 3.1 从内往外剥

1. `*scores` → 第 0 行首元素地址，类型 `int *`
2. `+ i*col + j` → 指针偏移，得到 `&arr[i][j]`，类型 `int *`
   注意：这一步**已经是地址**了，还没有取值！
3. `*( ... )` → 对地址解引用，**取出元素的值**（`arr[i][j]` 本身）
4. `&( ... )` → 再取这个值的地址 → 又变回 `&arr[i][j]`

### 3.2 结论

```c
&( * ( *scores + i*col + j ) )   ===   &arr[i][j]
```

因为 `&` 与 `*` 互逆：**`&*x` 等于 `x`（前提 x 是有效指针）**，
所以整串直接化简为：

```c
*scores + i * col + j      // 就是 &arr[i][j]
```

### 3.3 和"只加 j 就改值了吗"的疑问

有同学会问：`*(scores + i) + j` 这一步是不是把值改掉了？

❌ **不会！** 三个理由：

1. `*(scores + i)` 解引用后得到的是**一行的地址（`int *`）**，不是数值；
2. `+ j` 是在这个**地址上做指针偏移**，得到的是一个**新地址**；
3. **地址本身只是数字，不涉及任何写内存操作**。只有出现在赋值号 **左边**、并且外面套了解引用，才会写内存：

```c
*( *(scores + i) + j ) = 99;    // ✅ 这才是修改值
*(scores + i) + j;              // ❌ 只是算出地址，什么都没改
```

### 3.4 类型流转图

```
scores   : int (*)[col]   （行指针）
  + i    : int (*)[col]   （跳到第 i 行）
  *      : int [col] → int *  （这是【地址】，不是值！）
  + j    : int *          （仍是地址）
  *      : int            （这一步才是【值】）
  &      : int *          （又变回地址）
```

> 关键洞察：`*` 不一定是"取值"，它取出来的东西**可能是值，也可能是指针** —— 取决于被解引用对象的类型。

## 4. 函数指针：`(*pf)(mis)` 与 `pf(mis)` 有区别吗

### 4.1 结论

**在标准 C 中，两者完全等价，生成的机器码一模一样。**

```c
void (*pf)(char *);     // 函数指针，存放函数入口地址

(*pf)(mis);    // ✅ 显式解引用后调用（老教材、老代码风格）
pf(mis);       // ✅ 直接调用（现代工程最常用）
```

### 4.2 为什么 `pf(mis)` 也能调用

C 标准的两条特殊规则：

1. **函数名在表达式中自动退化为函数指针**：`ToUpper` 等价于 `&ToUpper`；
2. **函数指针可以直接当函数名使用**：调用时允许省略 `*`（这个 `*` 在函数指针上更接近"标记"，而不是真的取数据）。

```c
pf = ToUpper;      // ✅ 函数名自动转指针
pf = &ToUpper;     // ✅ 显式取地址，完全等价
```

### 4.3 ⚠️ 致命陷阱：`*pf(mis)` 是错的

运算符优先级：**`()`（函数调用） > `*`（解引用）**。

```c
*pf(mis);      // ❌ 被解析为 *( pf(mis) )
```

含义变成：先调用 `pf(mis)` 拿到返回值，再对返回值解引用。
如果函数返回 `void`（如 `void ToUpper(char *)`），直接编译报错。

**所以 `(*pf)(mis)` 里的括号绝对不能省！**

### 4.4 和普通数据指针的对比

| 指针类型 | 解引用 `*p` 得到什么 |
|---|---|
| `int *p` | 内存里的**数据（数值）** |
| `void (*pf)(char *)` | 仍然是**这个函数本身**（函数指针的 `*` 更接近语法标记） |

### 4.5 三种写法对照表

| 写法 | 是否合法 | 含义 |
|---|---|---|
| `(*pf)(mis)` | ✅ | 显式解引用后调用，可读性强 |
| `pf(mis)` | ✅ | 简写，等价，工程通用 |
| `*pf(mis)` | ❌ 编译报错 | 优先级错误，被解析为 `*(pf(mis))` |

### 4.6 口诀

> 带星就要带括号，不带星号直接调；
> 两种写法跑起来，机器码没差别。

## 5. 预处理指令全清单

### 5.1 总原则

- 全部以 `#` 开头，`#` 必须是**行首第一个非空白字符**；
- **末尾不加分号 `;`**！加了分号，分号会被一并展开进代码里，引发诡异 bug；
- 在**预处理阶段**执行，只做文本层面的事，**不做语法检查**。

### 5.2 分类全景

| 类别 | 指令 | 作用 |
|---|---|---|
| 文件包含 | `#include` | 原样插入文件内容 |
| 宏定义 | `#define` / `#undef` | 文本替换 / 取消定义 |
| 条件编译 | `#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` / `defined` | 按条件裁剪代码 |
| 杂项 | `#error` / `#pragma` / `#line` | 报错、编译器专有、改行号 |
| 内置宏 | `__FILE__` / `__LINE__` / `__DATE__` / `__TIME__` / `__func__` | 编译期自带信息 |

### 5.3 `#include`：两种写法

```c
#include <stdio.h>    // <>  ：先把系统/标准库路径翻一遍
#include "snake.h"    // ""  ：先在当前项目目录找，找不到再去系统路径
```

用途：把被包含文件内容**原样粘贴**到当前位置。

### 5.4 `#define`：纯文本替换（最容易翻车）

#### 常量宏

```c
#define PI 3.1415926
#define MAP_W 40
```

#### ⚠️ 经典优先级坑

```c
#define A 1+2
int b = A * 3;     // 展开为 1 + 2*3 = 7 ❌（想要 9）

// 正确写法：整体加括号
#define A (1+2)
```

#### 带参宏

```c
#define SQUARE(x) ((x)*(x))     // 参数和整体都要括号！
```

```c
#define BAD(x)  x*x
BAD(1+2)   // 展开成 1+2*1+2 = 5 ❌
```

#### 跨行宏

```c
#define LOG(fmt, ...)  printf(fmt "\n", __VA_ARGS__)   // C99 可变参数
#define BIG_MACRO  do { \
    step1();            \
    step2();            \
} while(0)
```

#### 取消宏

```c
#undef PI
```

### 5.5 条件编译（考试高频）

```c
// ① 若定义了 DEBUG
#ifdef DEBUG
    printf("debug: x=%d\n", x);
#endif

// ② 头文件保护（防重复包含）—— 必须掌握
#ifndef SNAKE_H
#define SNAKE_H
/* 头文件内容 */
#endif

// ③ 判断常量表达式
#if MAP_W > 40
    ...
#elif MAP_W == 40
    ...
#else
    ...
#endif

// ④ defined 运算符
#if defined(WIN32) || defined(LINUX)
```

#### `#ifdef` vs `#if`

| 指令 | 等价写法 | 能判断什么 |
|---|---|---|
| `#ifdef X` | `#if defined(X)` | **只判断有没有定义** |
| `#if` | — | 可判断数字、逻辑表达式（必须是**预处理期可算的常量**）|

#### `#pragma once` vs 头文件保护

```c
#pragma once
```

- 更简洁，现代编译器基本都支持；
- 但它**不是标准 C**，`#ifndef / #define / #endif` 才是标准、跨平台最稳的方案。

### 5.6 `#error`

```c
#if __cplusplus
#error "本文件只能用 C 编译器编译"
#endif
```

预处理阶段直接终止编译并打印信息。

### 5.7 `#pragma`

编译器专有，不保证跨编译器：

```c
#pragma pack(1)      // 结构体按 1 字节对齐（网络包、协议头常用）
#pragma GCC optimize("O2")
```

### 5.8 `#line`

```c
#line 100 "snake.c"    // 让后续代码的行号从 100 开始记
```

用于代码生成器/调试，日常几乎不写。

### 5.9 内置宏

```c
printf("%s:%d in %s\n", __FILE__, __LINE__, __func__);
printf("编译于 %s %s\n", __DATE__, __TIME__);
```

| 宏 | 含义 |
|---|---|
| `__FILE__` | 当前源文件名（字符串） |
| `__LINE__` | 当前行号（整数） |
| `__DATE__` / `__TIME__` | 编译日期 / 时间 |
| `__func__` | 当前函数名（C99，注意它是**变量式**的，不是宏） |

### 5.10 预处理阶段"不检查语法"的后果

```c
#define FOO(x) x+
int a = FOO(1) 2;    // 预处理展开成 1+ 2，编译阶段才发现问题
```

很多"看起来是宏写错"的报错，其实**报错位置在编译阶段**。

## 6. C 程序 6 个阶段（结合代码逐阶段讲解）

### 6.1 两个环境划分

> **翻译环境（前 4 步，编译器干活，产物落在磁盘）**：
> 预处理 → 编译 → 汇编 → 链接
> **运行环境（后 2 步，操作系统干活，程序真的在跑）**：
> 加载 → 执行

### 6.2 测试代码 `test.c`

```c
#include <stdio.h>
#define MAX 10

int main(void)
{
    int arr[MAX] = {1, 2, 3};
    for (int i = 0; i < 3; i++) {
        printf("%d ", arr[i]);
    }
    return 0;
}
```

下面全程拿它走一遍。

### 6.3 阶段 1：预处理 `gcc -E`　`.c → .i`

**本质：纯文本替换，不做语法检查，不生成任何机器码。**

做的事：

1. 展开 `#include`：把 `stdio.h` 全文**原样粘贴**进来（可能几千行）
2. 展开 `#define`：所有 `MAX` → `10`
3. 处理条件编译：删掉不成立的分支
4. 删除所有注释
5. 处理 `#error` / `#pragma` / `#line`、接续 `\` 跨行宏

`test.i` 的关键变化：

```c
/* ... stdio.h 几千行内容粘贴在这里 ... */

int main(void)
{
    int arr[10] = {1, 2, 3};       // MAX 已被替换成 10
    for (int i = 0; i < 3; i++) {
        printf("%d ", arr[i]);
    }
    return 0;
}
```

⚠️ 本阶段**不会**发现：少分号、类型错误、函数未定义。

### 6.4 阶段 2：编译 `gcc -S`　`.i → .s`（汇编文件）

**本质：C → 汇编，全部语法/类型检查都在这里。**

内部四小步：

1. **词法分析**：切成 token（`int`、`arr`、`[`、`10`、`]` …）
2. **语法分析**：按 C 语法构造语法树（少分号、括号不配在这里报错）
3. **语义分析**：类型检查（`char*` 赋给 `int` 在这里报错）
4. **优化 + 生成汇编**：产出目标平台汇编文本

`test.s` 简化版（x86-64）：

```asm
main:
    pushq   %rbp
    movq    %rsp, %rbp
    subq    $48, %rsp
    movl    $1, -48(%rbp)      # arr[0]
    movl    $2, -44(%rbp)      # arr[1]
    movl    $3, -40(%rbp)      # arr[2]
    movl    $0, -4(%rbp)       # i = 0
.L2:
    cmpl    $2, -4(%rbp)       # i <= 2 ?
    jg      .L3
    movl    -4(%rbp), %eax
    cltq
    movl    -48(%rbp,%rax,4), %esi
    leaq    .LC0(%rip), %rdi
    movl    $0, %eax
    call    printf              # ★ 只写了"调用 printf"，地址还不知道！
    addl    $1, -4(%rbp)
    jmp     .L2
.L3:
    movl    $0, %eax
    leave
    ret
```

> 重点：**这一步输出的是汇编文本，不是二进制，`printf` 的地址仍未知。**

### 6.5 阶段 3：汇编 `gcc -c`　`.s → .o`（目标文件）

**本质：汇编器把一条汇编翻译成一条机器码。**

- 产出目标文件（Linux `.o` / Windows `.obj`）；
- 里面已经是二进制机器指令；
- 但是：
  - **外部符号（`printf`）留下"待重定位"的空白缺口**；
  - 内部地址是段内偏移，不是最终运行地址。

一句话：这个 `.o` 知道"我要调用名叫 `printf` 的函数"，但**不知道它在哪**。

### 6.6 阶段 4：链接 `gcc test.o -o test`　`.o + 库 → 可执行文件`

**本质：三件大事。**

1. **合并段**：把多个 `.o` 的 `.text` / `.data` / `.bss` 拼到一起
2. **符号解析**：给每个未定义符号找定义。`printf` 不在你的 `.o` 里，在 libc
3. **重定位**：把阶段 3 留的缺口填上真实地址

两种链接方式：

| | 静态链接 | 动态链接（默认） |
|---|---|---|
| 做法 | 把库代码复制进可执行文件 | 只记录"运行时去加载 libc" |
| 体积 | 大 | 小 |
| 独立性 | 强 | 依赖系统库 |

⚠️ 本阶段报错 `undefined reference to 'xxx'`：
**不是语法错，是找不到符号定义**（忘了链接库、忘了写实现、函数名拼错）。

> 到这里，**翻译环境结束**，文件在磁盘上，还没运行。

### 6.7 阶段 5：加载（操作系统接管）

执行 `./test` 时，内核：

1. 把可执行文件读入内存；
2. 建立虚拟地址空间，映射各段：
   - `.text` 代码段（只读）
   - `.data` / `.bss` 数据段（全局/静态变量）
   - 栈（局部变量、函数调用）
   - 堆（`malloc`）
3. 动态链接：把 libc 映射进进程空间；
4. 运行时重定位，设置入口地址为 `_start`。

对应本例：给 `main` 分配栈帧，预留 `arr[10]` 和 `i` 的位置。

> 这一步**不属于编译器**，属于操作系统。

### 6.8 阶段 6：执行

CPU 从入口开始逐条取指、译码、执行：

1. 进入 `main`；
2. 栈上创建 `arr[10]`，前三个写 `1,2,3`，其余自动补 0；
3. `i=0`，判断 `i<3`；
4. 调用 `printf` 输出；
5. `i++` 循环；
6. `return 0` → 回到启动代码 → `exit()` → 进程结束。

### 6.9 全链路一张图

```
test.c
  ↓ 预处理（gcc -E）
test.i    ：stdio 粘贴、MAX→10、注释删除
  ↓ 编译（gcc -S）
test.s    ：汇编文本，call printf（地址未知）
  ↓ 汇编（gcc -c）
test.o    ：机器码，printf 地址缺口待重定位
  ↓ 链接（gcc -o test）
test      ：缺口填好，可执行文件，落在磁盘
  ↓ 加载（OS）
内存      ：虚拟地址空间、加载 libc、设置入口 _start
  ↓ 执行（CPU）
输出      ：1 2 3
```

### 6.10 分步命令速查

```bash
gcc -E test.c -o test.i     # 1 预处理
gcc -S test.i -o test.s     # 2 编译
gcc -c test.s -o test.o     # 3 汇编
gcc test.o -o test          # 4 链接
./test                      # 5+6 加载并执行
```

### 6.11 高频问答

- **`printf` 是在哪一步"找到"的？** → **链接阶段**（编译、汇编只留符号，不知道地址）。
- **语法错误在哪一步报？** → **编译阶段**。
- **宏写错的错在哪一步报？** → 先看是"展开后语法坏了"（编译阶段），还是"直接 `#error`"（预处理阶段）。
- **加载、执行算不算 GCC 的流程？** → **不算**，是操作系统运行环境。

## 7. `main` 与 `_start`：为什么程序会自动调用 main

> 先纠正拼写：是 `main`，不是 `mian`。

### 7.1 核心答案

**不是 CPU 认识 `main`，也不是操作系统直接跳 `main`。**
真正的入口是 libc 提供的启动代码 `_start`，它做完初始化**主动调用 `main`**。

> 如果拼成 `mian`，`_start` 找不到 `main` 符号 → **链接报错** `undefined reference to 'main'`。

### 7.2 完整调用链

```
操作系统 → 设置 rip = &_start
            ↓
         _start（libc 启动代码，汇编写的）
            ↓ 初始化栈、清 .bss、初始化 libc、准备 argc/argv
            ↓ call main
         main   ← 你写的业务代码
            ↓ return 0
         _start 拿到返回值
            ↓ call exit
         exit(0) → 进程终止，交还 OS
```

### 7.3 `_start` 具体做哪些准备

1. 建立 C 运行所需的栈环境；
2. 初始化 `.data` / 清零 `.bss`（全局变量、静态变量）；
3. 初始化 C 标准库内部结构（`malloc` 的堆管理、`stdio` 缓冲等）；
4. 准备 `argc` / `argv` / 环境变量；
5. **调用 `main(argc, argv)`**；
6. 接收返回值，调用 `exit()`。

伪汇编：

```asm
_start:
    ; 各种初始化 ...
    mov  argc, ...
    mov  argv, ...
    call main          ; 硬编码符号名 main
    mov  %eax, %edi    ; main 的返回值
    call exit
```

### 7.4 `_start` 是哪里来的

- 属于 C 标准库（libc）；
- 在**链接阶段**被链接器自动合并进你的可执行文件；
- 同时链接器把 ELF 头部 `e_entry` 字段设成 `_start` 的地址。

### 7.5 `return 0` 到底给了谁

```c
int main(void) { return 0; }
```

`return` 只是**从 main 返回到它的调用者 `_start`**，不是直接返回给操作系统。
`_start` 把 0 传给 `exit(0)`，操作系统才收到退出码。

也可以在 main 里直接 `exit(0)`，效果一样（跳过返回 `_start` 这一步）。

### 7.6 没有 main 也能跑吗

可以——裸机 / 自定义入口：

```bash
gcc -nostdlib -e mystart test.c -o test
```

- `-nostdlib`：不链接标准库（也就没有 `_start`）；
- `-e mystart`：把入口设为 `mystart`。

嵌入式无 OS 场景同理：启动汇编里写死跳到 `Reset_Handler`，再调 `main`。

## 8. 为什么只能有一个入口

分两层看：**操作系统/硬件层** 与 **C 标准/链接层**。

### 8.1 硬件层：CPU 只有一个指令指针 `rip`

进程启动时，硬件只需要知道一件事：**第一条指令在哪**。
CPU 的工作循环是"取指 → 译码 → 执行"，取指地址由 `rip` 决定，**`rip` 只有一个值**。

> 类比：按下播放键，播放器只能从一个时间点开始播，不可能同时从两处开始。

### 8.2 可执行文件格式层：只有一个入口字段

| 格式 | 入口字段 | 数量 |
|---|---|---|
| Linux ELF | `e_entry` | 1 个 |
| Windows PE | `AddressOfEntryPoint` | 1 个 |

字段本身只存**一个地址**，所以一个可执行文件**只能登记一个启动点**。

### 8.3 链接层：重复 `main` 会直接报错

```c
int main() { ... }
int main() { ... }
```

两个 `.o` 都定义了符号 `main` → 链接器报 `multiple definition of 'main'`。

原因：`_start` 里有一条 `call main`，**只能绑定到一个符号地址**；出现两份实现就产生歧义。

> 区分：
> - **普通函数**：想写多少个都行（`snake_step`、`game_tick`、`snake_init`）；
> - **被启动代码引用的那个符号（默认 `main`）**：只能有一份实现。

### 8.4 混淆点：这些都不是"多入口"

| 概念 | 是什么 | 是否违反"唯一入口" |
|---|---|---|
| 动态库 `.so` 的导出函数 | 库对外提供的 API，可被任意调用 | ❌ 不算（库本身不是可执行程序，没有 `e_entry`） |
| 多线程 | 程序**跑起来之后**自己创建的执行流 | ❌ 不算（是运行时分叉，不是启动双起点） |
| 多个独立程序 | 每个 exe 各自有一个入口 | ❌ 不算（各自独立） |
| 自定义 `-e foo` | 换一个入口 | ✅ 换了，但**仍然只有一个** |

### 8.5 真要"两个起点"怎么办

在唯一入口里自己分发：

```c
void entry(void)     // 唯一真正入口
{
    start_partA();
    start_partB();
}
```

或者创建线程并发。**所有并行，都是从这一个起点之后分叉出来的。**

### 8.6 一句话考点版

> 可执行文件只能有一个入口，根源是：**硬件指令指针唯一 + 可执行文件格式只支持登记一个启动地址**。
> `main` 只是启动代码约定调用的函数名，不是操作系统直接识别的入口。

## 9. 十六进制 `0x` 前缀与换算

### 9.1 基本规则

`0x` / `0X` 表示**十六进制字面量**，基数 16，可用字符 `0-9` `a-f` `A-F`。

```c
int a = 0x10;    // 16
int b = 010;     // 八进制 → 8
int c = 10;      // 十进制 → 10
int d = 0b1010;  // 二进制（GCC / C23 扩展）
```

### 9.2 换算原理：每一位权重是 16 的幂

$$
\text{值} = \sum_{k=0}^{n-1} d_k \cdot 16^{k}
$$

（$d_k$ 从右往左，第 0 位是最低位）

#### 逐个验算

**`0x0F`**

```
0x0F = 0 × 16^1 + 15 × 16^0
     = 0 + 15
     = 15
```

**`0x10`**

```
0x10 = 1 × 16^1 + 0 × 16^0
     = 16 + 0
     = 16
```

**`0xFF`**

```
0xFF = 15 × 16^1 + 15 × 16^0
     = 240 + 15
     = 255
```

**`0x100`**

```
0x100 = 1 × 16^2 + 0 × 16^1 + 0 × 16^0
      = 1 × 256 + 0 + 0
      = 256
```

### 9.3 规律一眼看懂

| 十六进制 | 十进制 | 备注 |
|---|---|---|
| `0x01` | 1 | |
| `0x0F` | 15 | 4 位二进制全 1 |
| `0x10` | 16 | 进位点 |
| `0xFF` | 255 | 1 字节最大值（`unsigned char` 上限） |
| `0x100` | 256 | 进到第 3 位 |
| `0xFFFF` | 65535 | 2 字节最大值 |

> 口诀：**十六进制逢 16 进一。两位十六进制最大 `0xFF`=255，再加 1 就进位成三位 `0x100`=256。**

### 9.4 通用例子

```c
0x2A3 = 2×256 + 10×16 + 3 = 512 + 160 + 3 = 675
```

### 9.5 为什么 C 里到处是十六进制

1. **地址 / 指针值**：`%p` 默认输出 `0x...`，内存地址天然按字节对齐，十六进制位数整齐；
2. **位运算 / 掩码 / 寄存器**（嵌入式、操作系统、网络协议）：

```c
#define FLAG_A 0x01
#define FLAG_B 0x02
#define MASK   0x0F
```

3. **字节常量**：`char ch = 0x41; // 'A'`

### 9.6 输出格式

```c
printf("%x",  255);    // ff      （不带前缀）
printf("%#x", 255);    // 0xff    （带前缀）
printf("%X",  255);    // FF      （大写）
printf("%08x",255);    // 000000ff（补零到 8 位）
```

### 9.7 易错点

- ❌ 把 `0x10` 当成 10（实际是 16）
- ❌ 把 `010` 当成 10（实际是 8，**八进制是 C 的历史坑**）
- ❌ 写 `0x` 后面跟非法字符，如 `0xG1`
- ⚠️ `0x` 前缀本身不计入数值

## 10. `void *` 为什么"接受得了但用不了"

### 10.1 现象

```c
void *p = malloc(100);   // ✅ 可以
p + 1;                   // ❌ 编译报错
*p;                      // ❌ 编译报错
```

**不是存不下地址，而是编译器缺"这个指针指向的东西多大、是什么布局"的信息。**

### 10.2 硬件层：所有指针长得一模一样

在内存、CPU、地址总线眼里：

- `void *`、`int *`、`Point *`、`char *` 存的东西**完全相同：就是一个地址数字**（如 `0x55f8a7b2c000`）；
- 64 位平台：所有指针都是 **8 字节**；32 位：4 字节。

> **硬件不区分指针类型。类型纯粹是 C 编译器的元信息。**

### 10.3 类型到底记录了什么

任何 `T *p`，编译器记两件事：

1. **起始地址**（那个数字）
2. **步长 = `sizeof(T)`**

| 指针 | `p + 1` 实际加多少 |
|---|---|
| `char *` | 1 字节 |
| `int *` | 4 字节 |
| `Point *` | `sizeof(Point)` |
| `void *` | **无法确定 → 禁止运算** |

`sizeof(void)` 在标准 C 中是**未指定的**（GCC 扩展为 1，但不合法用于算术）。

`p + 1` 编译器心里要算：`地址 + 1 * sizeof(*p)`；`sizeof(void)` 没有意义 → 报错。
`*p` 编译器要算：从该地址读出 `sizeof(*p)` 字节、按对应类型解释 → `void` 没有值和大小 → 报错。

> 一句话：**硬件给得起地址，编译器给不出步长和解引用尺寸，所以拒绝。**

### 10.4 为什么 `void *` 又能直接赋给 `Point *`

C 标准的一条特殊规则：

> **`void *` 可以与任意"对象指针"互相隐式转换。**

```c
Point *body = malloc(cap * sizeof(Point));   // ✅ 隐式转换
```

过程：`malloc` 返回一个"裸地址"；赋值的一瞬间，编译器给这个地址**贴上 `Point *` 的标签**，从此 `body + 1` 就知道加 `sizeof(Point)`。

**地址数字不变，只换了标签。**（C++ 这里要求强制转换，两边有区别。）

### 10.5 ⚠️ `void **` 不是万能

```c
void **p;
Point **body = p;      // ❌ 不允许隐式转换！
```

`void *` 万能，**`void **` 不万能**。
`void **` 的含义是"指向一个 `void *` 变量的指针"，标签不同，不能自动转换。需要显式强转。

### 10.6 那什么时候 `void *` 完全可用

只做**地址搬运**时完全合法：

```c
void log_ptr(void *p) {
    printf("%p\n", p);      // ✅ 只打印地址，解引用/算数都不做
}
```

只要不涉及 `*`、`+`、`[]`，`void *` 就是安全的。

### 10.7 为什么 `memcpy` / `memset` 参数是 `void *`

因为它们要处理**任意类型**的内存，且内部会转成 `unsigned char *` 按**字节**逐粒搬运：

```c
void *memcpy(void *dest, const void *src, size_t n)
{
    unsigned char *d = dest;      // 转成字节指针，步长固定 1
    const unsigned char *s = src;
    while (n--) *d++ = *s++;
    return dest;
}
```

> `char *` 之所以"万能"，正是因为它的步长恒定为 1 字节。

### 10.8 类型流转总结表

| 指针 | 能存地址 | 能 `+1` | 能 `*p` | 能 `p[i]` |
|---|---|---|---|---|
| `char *` | ✅ | ✅ +1 字节 | ✅ | ✅ |
| `int *` | ✅ | ✅ +4 字节 | ✅ | ✅ |
| `Point *` | ✅ | ✅ +sizeof(Point) | ✅ | ✅ |
| `void *` | ✅ | ❌ | ❌ | ❌ |
| `void **` | ✅ | ✅（+8 字节） | ✅（得到 `void*`） | ✅（得到 `void*`） |

## 11. 贪吃蛇项目中的 C 知识点串讲

> 这份项目代码几乎把 C 的核心难点全用上了，是天然的复习素材。

### 11.1 基础类型定义（项目大致形态）

```c
typedef struct Point {
    int x, y;
} Point;

typedef struct Snake {
    Point *body;     // 蛇身：堆上的动态数组
    int len;         // 当前长度
    int cap;         // 已分配容量（扩容用）
    int dir;         // 当前方向
} Snake;

typedef struct Game {
    Snake *snake;
    char *cells;     // 地图：一维连续内存，模拟二维格子
    int w, h;
} Game;

typedef void (*DirHandler)(Snake *);        // 方向处理函数指针类型

typedef struct KeyBind {
    int key;
    DirHandler handler;
} KeyBind;
```

### 11.2 `struct` + `typedef`

- **`struct`**：把不同类型数据打包成一个整体，描述一个"事物"；
- **`typedef`**：给类型起别名，省掉每次写 `struct`。

```c
struct Point p1;    // 不用 typedef 时
Point p2;           // 用了 typedef 之后
```

⚠️ 坑：`typedef` 只是重命名，不是定义变量；给指针起别名时多变量声明容易看错：

```c
typedef Point* PPoint;
PPoint a, b;    // ✅ a、b 都是指针（如果写成 Point *a, b 则 b 不是指针！）
```

### 11.3 `p->member`：结构体指针访问成员

```c
Snake *s;
s->len;      // 等价 (*s).len
s->body;     // 等价 (*s).body
```

- 变量用 `.`：`g.w`
- 指针用 `->`：`g->w`
- `->` 内部就是"先解引用，再取成员"，是结构体项目最高频语法。

### 11.4 一级指针传参修改外部数据

```c
void snake_step(Snake *s)     // 传地址，能改外面的蛇
{
    s->len++;
    s->dir = ...;
}

void game_tick(Game *g)
{
    snake_step(g->snake);
    ...
}
```

**C 是值传递**：

| 传参方式 | 函数内改动 | 外部原对象 |
|---|---|---|
| `Snake s`（值） | 改的是**副本** | ❌ 完全不变 |
| `Snake *s`（地址） | 通过地址改原内存 | ✅ 生效 |

> 一级指针解决的是：**改"指针指向的那块内存里的内容"**。

### 11.5 `malloc` / `free`：`game_init` 地图、`snake_init` 身体

```c
// 分配地图一整块连续内存
g->cells = malloc(g->w * g->h * sizeof(char));

// 分配蛇身初始数组
s->body = malloc(INIT_CAP * sizeof(Point));
```

要点：

- `malloc` 在**堆**分配，返回 `void *`（C 里可隐式转成目标指针）；
- 堆内存**不会**随函数退出自动释放，生命周期由程序员掌控；
- 失败返回 `NULL`，**必须检查**；
- `free(p)` 后指针变**野指针**，最好立刻 `p = NULL`；
- 不能 free 栈地址，不能重复 free（double free）。

### 11.6 ★重点：`realloc + 二级指针`（`snake_reserve`）

#### 场景

蛇变长，需要扩容身体数组。

#### ❌ 错误写法：一级指针

```c
void snake_reserve_bad(Point *body, int *cap, int need)
{
    if (need > *cap) {
        *cap = need * 2;
        body = realloc(body, *cap * sizeof(Point));   // ❌ 只改函数内局部副本！
    }
}
```

`body` 是**局部变量（一份拷贝）**，`realloc` 后新地址赋给它，函数一返回就丢了；
主调方 `s->body` **仍然指向旧地址**，而旧内存可能已被 realloc 释放/搬迁 → **野指针 / 悬垂指针**。

#### ✅ 正确写法：二级指针

```c
bool snake_reserve(Point **body, int *cap, int need)
{
    if (need <= *cap) return true;

    int new_cap = *cap ? *cap * 2 : 4;
    while (new_cap < need) new_cap *= 2;

    Point *tmp = realloc(*body, new_cap * sizeof(Point));   // ★ 先用临时变量接
    if (tmp == NULL) return false;                          // 失败时原指针依然有效

    *body = tmp;         // ★ 通过二级指针，修改【外部那个指针变量】存的地址
    *cap = new_cap;
    return true;
}

// 调用：传指针的地址
snake_reserve(&s->body, &s->cap, s->len + 1);
```

#### 核心区分（务必记牢）

| 需求 | 该传什么 | 例子 |
|---|---|---|
| 改「指针指向的数据」 | 一级指针 | `game_tick(Game *g)` → 改 `g->snake` 的内容 |
| 改「指针本身存的地址」 | **二级指针** | `snake_reserve(Point **body)` → 改 `s->body` 这个指针变量 |

#### 为什么 `realloc` 一定要用临时变量

```c
*body = realloc(*body, size);   // ❌ 失败时返回 NULL，旧地址直接丢失 → 内存泄漏
```

`realloc` 失败返回 `NULL`，并且**原内存块仍然有效**。必须：

```c
Point *tmp = realloc(*body, size);
if (!tmp) return false;         // 原 *body 还在，安全退出
*body = tmp;
```

#### `realloc` 的两个行为

1. 原地扩容（后面空间够）：返回**同一地址**；
2. 搬家扩容（后面不够）：分配新块、拷贝数据、释放旧块，返回**新地址**。
→ 正因为可能搬家，才必须回写外部指针。

### 11.7 指针算术遍历：`for (p = body; p < body + len; p++)`

```c
Point *p;
for (p = body; p < body + s->len; p++) {
    // *p 就是当前这一节蛇身的坐标
    plot(p->x, p->y);
}
```

知识点：

- `body + len`：指针加法，跳 `len` 个 `Point`；
- `p++`：每轮跳一个 `Point`；
- **指针比较 `<` 只允许在同一块连续数组内**，跨数组比较是 UB；
- 与第 1 节联动：这里若写 `*p + 1` 就是"坐标值 +1"，写 `*(p+1)` 是"下一节" —— 一字之差，含义完全不同。

### 11.8 一维模拟二维：`cells + y * MAP_W + x`

```c
char *cell_at(Game *g, int x, int y)
{
    return g->cells + y * g->w + x;   // 二维坐标 → 一维偏移
}
```

原理：

- `g->cells` 是 `char *`（步长 1 字节）；
- 偏移公式：**`index = y * width + x`**；
- 返回 `char *`：拿到格子地址，调用方既能读 `*cell_at(...)`，也能写 `*cell_at(...) = '#'`。

👉 **和第 2 节 `*scores + i*col + j` 是同一个套路**：把二维拍平成一维，用手算 offset 替代二维下标。

⚠️ 与 `char **` 区分：

| 形态 | 内存 | 能用 `y*w+x` 吗 |
|---|---|---|
| `char *cells`（一维模拟） | 一整块连续 | ✅ |
| `char **rows`（指针数组） | 每行单独 malloc，分散 | ❌ 不行 |

### 11.9 `const` 只读指针：`snake_hits_self(const Snake *, const Point *)`

```c
bool snake_hits_self(const Snake *s, const Point *head)
{
    // 只读蛇、只读头坐标，绝不修改
}
```

`const` 放在 `*` 不同位置，含义完全不同（面试必考）：

| 写法 | 指针本身可改指向 | 指向的内容可改 | 读法 |
|---|---|---|---|
| `const Snake *s` | ✅ 可以改 s 指向谁 | ❌ 不能通过 s 改蛇 | 指向"只读 Snake"的指针 |
| `Snake * const s` | ❌ 不能改指向 | ✅ 可以改蛇内容 | "只读指针"，指向可写数据 |
| `const Snake * const s` | ❌ | ❌ | 两者都锁死 |

快速判读口诀：**`const` 在读法上从右往左读，紧挨着 `*` 左边就是"内容只读"，紧挨着变量名就是"指针只读"。**

作用：

1. 编译器帮你拦截误写（一写就报错）；
2. 接口语义清晰：告诉调用方"我不会改你的数据"；
3. 使得 `const Snake *` 能接收 `Snake *` 和 `const Snake *` 两种实参，更通用。

### 11.10 函数指针 + 表驱动：`DirHandler` + `BINDS[]`

```c
typedef void (*DirHandler)(Snake *);

static void go_up(Snake *s)    { s->dir = DIR_UP;    }
static void go_down(Snake *s)  { s->dir = DIR_DOWN;  }
static void go_left(Snake *s)  { s->dir = DIR_LEFT;  }
static void go_right(Snake *s) { s->dir = DIR_RIGHT; }

static const KeyBind BINDS[] = {
    { 'w', go_up    },
    { 's', go_down  },
    { 'a', go_left  },
    { 'd', go_right },
    { 0,   NULL     },     // 哨兵项，遍历时用来判断结束
};

void handle_key(Snake *s, int key)
{
    for (const KeyBind *b = BINDS; b->handler != NULL; b++) {
        if (b->key == key) {
            b->handler(s);          // 等价 (*b->handler)(s)
            return;
        }
    }
}
```

知识点：

1. **函数指针**：保存函数入口地址，类型要写全（返回类型 + 参数列表）；
2. **表驱动编程**：用数组 + 查表替代一长串 `if / else if`，可读性和扩展性都更好；
3. 调用写 `b->handler(s)` 或 `(*b->handler)(s)` 都行（见第 4 节）；
4. **哨兵项 `{0, NULL}`**：让遍历有终止条件，不必额外记数组长度；
5. `static` 修饰函数：限制在本文件内可见，避免符号冲突。

### 11.11 `memset` + 数组首地址：`clear_cells`

```c
#include <string.h>

void clear_cells(Game *g)
{
    memset(g->cells, 0, (size_t)g->w * g->h);   // 逐个字节清零
}
```

`memset(void *dest, int fill_byte, size_t n)`：

- 从 `dest` 起，把**接下来 n 个字节**全部写成 `fill_byte`；
- 参数是 `void *`，所以能接收任意类型数组的首地址（见第 10 节）。

⚠️ **超经典坑：memset 是按"字节"填充**

```c
int arr[10];
memset(arr, 1, sizeof(arr));    // ❌ 不是把每个 int 设成 1！
// 每个字节变成 0x01，一个 int 变成 0x01010101 = 16843009

memset(arr, 0, sizeof(arr));    // ✅ 只有填 0 对 int 数组是安全的
```

| 目标类型 | `memset(..., 0, ...)` | `memset(..., 非0, ...)` |
|---|---|---|
| `char` 数组 | ✅ | ✅ |
| `int` / 指针数组 | ✅ | ❌ 结果错误 |

### 11.12 一整条主线串起全部

```
初始化：
   结构体组织数据（struct + typedef）
   malloc 在堆上分配地图、蛇身
   一级指针传参，改结构体内容（game_init / snake_init）
        ↓
蛇变长：
   realloc 扩容 + 二级指针回写新地址（snake_reserve(Point **body)）
        ↓
遍历蛇身：
   指针算术，沿连续内存逐节访问（p < body + len; p++）
        ↓
访问格子：
   y*w + x 把二维拍平成一维，指针偏移（cells + y*w + x）
        ↓
碰撞检测：
   const 指针，只读不改（snake_hits_self(const Snake *, const Point *)）
        ↓
按键控制：
   函数指针 + 数组查表，分发到各方向函数（BINDS[]）
        ↓
清空地图：
   memset 按字节批量清零（memset(g->cells, 0, w*h)）
```

## 12. 易错点总清单

### 12.1 指针运算

- [ ] ❌ 以为 `*p + 1` 结果是指针 → **`*p` 是数值，结果 11，不是 20**
- [ ] ❌ 以为 `*p + 1` 等价 `*(p+1)` → **完全不同**
- [ ] ❌ 以为 `p + 1` 是地址加 1 字节 → **加 `sizeof(指向类型)`**
- [ ] ❌ `*p++` 当成"先加后取" → **后缀是先取值、后自增**
- [ ] ❌ `(*p)++` 当成"指针前移" → **是值自增，指针不动**
- [ ] ❌ 忘了 `(*p)++` 会真的改内存（`arr[0]` 变 11）
- [ ] ❌ 拿不同数组的两个指针比较大小 → UB

### 12.2 二维与数组指针

- [ ] ❌ 把 `*(scores+i)+j` 和 `*scores+i*col+j` 当同义 → 连续内存下结果同，但**语义/类型不同**
- [ ] ❌ 对 `int **scores` 用 `i*col+j` 拍平 → **行分散，直接越界**
- [ ] ❌ 以为 `*(scores+i)` 取出的是数值 → 它是**行首地址（指针）**
- [ ] ❌ 以为 `+j` 会改值 → 只是算地址，**赋值号左边才会写内存**
- [ ] ❌ 看漏 `&*` 互逆 → `&(*(expr))` 就等于 `expr`

### 12.3 函数指针

- [ ] ❌ 写 `*pf(mis)` → **优先级错误，解析成 `*(pf(mis))`，编译报错**
- [ ] ❌ 以为 `pf(mis)` 不合法 → **合法，等价于 `(*pf)(mis)`**
- [ ] ❌ `pf = ToUpper` 和 `pf = &ToUpper` 当不同 → 完全等价
- [ ] ❌ 函数指针类型写不全（漏参数或返回类型）

### 12.4 预处理

- [ ] ❌ 预处理指令末尾加分号 → 分号被展开进代码
- [ ] ❌ `#define A 1+2` 不加括号 → `A*3` 变成 `7`
- [ ] ❌ 带参宏参数不加括号 → `SQUARE(1+2)` 出错
- [ ] ❌ 以为预处理阶段能报语法错误 → **不检查语法**
- [ ] ❌ 混用 `#ifdef X` 与 `#if defined(X)` 的适用范围
- [ ] ❌ 头文件不做保护 → 重复包含导致重复定义
- [ ] ❌ 以为 `#pragma once` 是标准 C → 那是编译器扩展

### 12.5 编译/链接/运行

- [ ] ❌ 以为预处理阶段能发现少分号 → **编译阶段才报**
- [ ] ❌ 以为 `undefined reference` 是语法错 → **是链接阶段找不到符号**
- [ ] ❌ 以为 `printf` 在编译阶段就"找到"了 → **链接阶段**
- [ ] ❌ 把"加载、执行"算进 GCC 流程 → **属于操作系统**
- [ ] ❌ 以为 `main` 直接返回给操作系统 → **返回给 `_start`，再由 `exit()` 交给 OS**
- [ ] ❌ 以为操作系统认识 `main` → **认识的是 `_start`**

### 12.6 入口

- [ ] ❌ 以为程序入口就是 `main` → 默认是 `_start`
- [ ] ❌ 以为可以有多个启动入口 → **`rip` 与 `e_entry` 都只有一个**
- [ ] ❌ 把"库导出函数多""多线程"当成多入口
- [ ] ❌ 函数名拼成 `mian` → 链接报 `undefined reference to 'main'`

### 12.7 `void *`

- [ ] ❌ 以为 `void *` 不能存地址 → **能存，只是不能解引用/做算术**
- [ ] ❌ 以为 `void **` 和 `Point **` 一样万能 → **不能隐式转换**
- [ ] ❌ 以为指针类型影响硬件 → **类型只是编译器元信息**
- [ ] ❌ 忘了 `malloc` 返回的 `void*` 在 C 里可隐式转成任意对象指针

### 12.8 贪吃蛇项目

- [ ] ❌ `realloc` 用一级指针 → **只改局部副本，外部指针失效/悬垂**
- [ ] ❌ `*body = realloc(*body, n)` → **失败时丢旧地址，内存泄漏**
- [ ] ❌ 混淆"改内容（一级指针）"与"改指针地址（二级指针）"
- [ ] ❌ 用 `y*w+x` 访问 `char **` 行指针数组 → **行不连续，越界**
- [ ] ❌ `memset` 给 `int` 数组填非 0 → **按字节填，结果错误**
- [ ] ❌ `const Snake *` 与 `Snake * const` 理解反了
- [ ] ❌ `free` 之后继续用指针（野指针）
- [ ] ❌ `free` 后未置 `NULL`，后续判空失效

## 13. 自测题（带答案）

### Q1（指针运算）
```c
int a[] = {5, 6, 7};
int *p = a;
printf("%d %d\n", *p + 1, *(p + 1));
```
输出是什么？`a[0]` 有没有被改？

<details>
<summary>答案</summary>

输出 `6 6`。
`*p + 1` → `5 + 1 = 6`（数值加法）；
`*(p + 1)` → `a[1] = 6`。
`a[0]` **没被改**（仍是 5），p 也没动。
</details>

### Q2（`*p++`）
```c
int a[] = {1, 2};
int *p = a;
printf("%d\n", *p++);
printf("%d\n", *p);
```
两行分别输出？

<details>
<summary>答案</summary>

`1` 和 `2`。
`*p++` 取旧值 1，之后 p 指向 `a[1]`；第二行输出 2。
</details>

### Q3（`(*p)++`）
```c
int a[] = {10};
int *p = a;
printf("%d\n", (*p)++);
printf("%d\n", a[0]);
```

<details>
<summary>答案</summary>

输出 `10` 和 `11`。
表达式结果是旧值 10，但 `a[0]` 已经被加成 11。
</details>

### Q4（二维偏移）
```c
int arr[2][3] = {{1,2,3},{4,5,6}};
int (*s)[3] = arr;
```
`*(*(s + 1) + 2)` 和 `*(*s + 1*3 + 2)` 各是多少？

<details>
<summary>答案</summary>

都是 `6`（即 `arr[1][2]`）。
路径不同：前者先跳 1 行再跳 2 列；后者从第 0 行起点直接跳 `1*3+2 = 5` 个 int。
</details>

### Q5（`&*` 化简）
```c
&( * ( *scores + i*col + j ) )
```
能化简成什么？会修改值吗？

<details>
<summary>答案</summary>

化简成 `*scores + i*col + j`，也就是 `&scores[i][j]`。
**不会修改任何值**，整条只是算地址。
</details>

### Q6（函数指针）
```c
void (*pf)(char *);
```
下面哪个正确？A. `(*pf)(s);` B. `pf(s);` C. `*pf(s);`

<details>
<summary>答案</summary>

A、B 正确且等价；C 错误。
C 被解析成 `*(pf(s))`，函数返回 `void`，报错。
</details>

### Q7（预处理）
```c
#define A 1+2
int b = A * 3;
```
b 等于多少？怎么改才安全？

<details>
<summary>答案</summary>

`b = 1 + 2*3 = 7`。
改成 `#define A (1+2)`，则 `b = (1+2)*3 = 9`。
</details>

### Q8（六阶段）
`printf` 的地址是在哪个阶段确定的？语法错误在哪个阶段报？

<details>
<summary>答案</summary>

`printf` 地址在**链接阶段**确定（重定位补缺口）；
语法错误在**编译阶段**报（预处理不查语法）。
</details>

### Q9（入口）
`main` 的 `return 0` 直接返回给谁？程序真正入口是什么？

<details>
<summary>答案</summary>

`return` 返回给调用者 **`_start`**，再由 `_start` 调用 `exit(0)` 交还操作系统。
程序真正的入口符号是 **`_start`**（libc 启动代码），不是 `main`。
</details>

### Q10（唯一入口）
为什么一个可执行文件只能有一个启动入口？

<details>
<summary>答案</summary>

两层原因：
① 硬件：CPU 只有一个指令指针 `rip`，进程启动只能设一个起始地址；
② 文件格式：ELF 的 `e_entry` / PE 的 `AddressOfEntryPoint` 只存一个地址。
C 的 `main` 只是 `_start` 里硬编码调用的符号，重复定义会导致链接歧义。
</details>

### Q11（十六进制）
`0x100` 等于十进制多少？`0x2A3` 呢？

<details>
<summary>答案</summary>

`0x100 = 1*256 = 256`；
`0x2A3 = 2*256 + 10*16 + 3 = 675`。
</details>

### Q12（`void *`）
```c
void *p = malloc(16);
p + 1;
```
为什么报错？底层发生了什么？

<details>
<summary>答案</summary>

硬件层 `void *` 只是一个地址数字，和其他指针一样；但**类型是编译器元信息**。
`p + 1` 需要 `sizeof(void)` 作为步长，而 `void` 无大小 → 编译期拒绝。
赋给 `int *ip = p;` 之后就有步长（4 字节），可以正常算。
</details>

### Q13（realloc + 二级指针）
为什么扩容蛇身必须传 `Point **body`？

<details>
<summary>答案</summary>

`realloc` 可能返回**新地址**，需要把这个新地址写回**主调方的指针变量** `s->body`。
如果传一级指针 `Point *body`，函数内 `body = realloc(...)` 只改了局部副本，返回后丢弃，
外部 `s->body` 仍指向旧地址 → 野指针 / 悬垂指针。
传 `Point **body` 才能通过 `*body = tmp` 修改外部指针本身。
</details>

### Q14（memset）
```c
int a[10];
memset(a, 1, sizeof(a));
```
得到的是"每个 int = 1"吗？

<details>
<summary>答案</summary>

**不是。** `memset` 按字节填，每个字节 = `0x01`，一个 int 变成 `0x01010101 = 16843009`。
只有填 `0` 对 int 数组安全。
</details>

### Q15（const）
`const Snake *s` 和 `Snake * const s` 有什么区别？

<details>
<summary>答案</summary>

- `const Snake *s`：**指向只读数据的指针** —— 不能通过 s 改蛇，但 s 可以换指向；
- `Snake * const s`：**只读指针** —— s 不能改指向，但可以通过它改蛇的内容。
</details>
