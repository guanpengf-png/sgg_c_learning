# 第一部分　指针的本体

## 第 1 章　指针加法的唯一铁律

### ① 一句话结论

```
指针 + n  →  实际地址增量 = n × sizeof(指针所指向的类型)
```

一句话：**指针走一步，走的是"它指向的那个东西"的大小，不是它自己的大小。**

### ② 为什么

指针变量里存的是一个**地址数字**（64 位机器上 8 字节）。
但这个数字不是随便加减的，编译器在算 `p + n` 时会自动乘上元素大小，因为底层要索引数组：

```
某类型 T 的数组： arr[i] 的内存地址 = arr起始 + i * sizeof(T)
```

编译器把 `p + n` 编译成 `p + n * sizeof(*p)`，这样 `p+1` 正好落在下一个元素上，不用你手算。

### ③ 代码例子（直接能跑）

```c
#include <stdio.h>

int main(void)
{
    int    a[3] = {10, 20, 30};
    int   *pi   = a;          // 指向 int
    char   c[6] = "hello";
    char  *pc   = c;          // 指向 char

    printf("pi     = %p\n", (void *)pi);
    printf("pi + 1 = %p  (差 %ld)\n", (void *)(pi + 1), (long)((char *)(pi + 1) - (char *)pi));
    printf("pc     = %p\n", (void *)pc);
    printf("pc + 1 = %p  (差 %ld)\n", (void *)(pc + 1), (long)((pc + 1) - pc));
    return 0;
}
```

输出（地址是示例）：

```
pi     = 0x7ffe1000
pi + 1 = 0x7ffe1004  (差 4)     ← int 是 4 字节
pc     = 0x7ffe1010
pc + 1 = 0x7ffe1011  (差 1)     ← char 是 1 字节
```

### ④ 常见步长速查

| 指针类型 | `+1` 的地址增量 |
|---|---|
| `char *` | 1 |
| `short *` | 2 |
| `int *` | 4 |
| `long *` / `double *` | 8 |
| `int (*)[5]` | 20（一整行 5 个 int） |
| `char (*)[6]` | 6（一整组 6 个 char） |

### ⑤ 易错点

- ❌ 不要以为"指针都是 8 字节，所以 +1 就是 +8"。**指针自己多大，和 +1 跳多远，是两个概念。**
- ❌ `void *` 不能直接做 `+1`（标准 C 不允许，GCC 扩展里按 1 字节算）。

## 第 2 章　`char *` 与 `char (*q)[6]`：一字之差，步长 6 倍

### ① 一句话结论

```c
char *str;        // 指向「一个 char」         → +1 走 1 字节
char (*q)[6];     // 指向「一整个 char[6]」    → +1 走 6 字节
```

两者都是"指向 char 相关"的指针，但**粒度不同**：前者看单个字符，后者看一整组 6 个字符的数组。

### ② 为什么

拆声明（螺旋法则，从变量名往外读）：

```c
char *str;
```
1. `str` 是一个指针
2. `*` 指向的是 `char`
→ 一组整体 = 一个 char，`sizeof` 是 1。

```c
char (*q)[6];
```
1. 括号把 `*q` 绑定在一起 → `q` 是一个指针
2. `[6]` → 它指向一个有 6 个元素的数组
3. `char` → 数组元素是 char
→ 一组整体 = `char[6]`，`sizeof` 是 6。

### ③ 代码例子

```c
#include <stdio.h>

int main(void)
{
    char arr[] = "hello";        // char[6]：h e l l o \0
    char *str     = arr;         // ✅ arr 自动退化为 char*
    char (*q)[6]  = &arr;        // ✅ &arr 的类型就是 char (*)[6]

    printf("str   = %p\n", (void *)str);
    printf("str+1 = %p\n", (void *)(str + 1));     // +1
    printf("q     = %p\n", (void *)q);
    printf("q+1   = %p\n", (void *)(q + 1));       // +6

    printf("字符逐个地址：\n");
    for (int i = 0; i < 6; i++)
        printf("  str+%d = %p      &(*q)[%d] = %p\n",
               i, (void *)(str + i), i, (void *)&(*q)[i]);
}
```

### ④ 关键对比表

| | `char *str` | `char (*q)[6]` |
|---|---|---|
| `sizeof(*变量)` | 1 | 6 |
| `+1` 增量 | +1 字节 | +6 字节 |
| 正确的取值写法 | `str[i]` / `*(str+i)` | `(*q)[i]` |
| 正确赋值来源 | `arr`（数组名） | `&arr`（整个数组） |
| 常见用途 | 字符串操作 | 二维数组行指针 |

### ⑤ 易错点（昨天实际踩到的）

- ❌ `char (*q)[6] = arr;` —— 类型不匹配。`arr` 是 `char*`，`&arr` 才是 `char (*)[6]`
- ❌ 忘了括号写成 `char *q[6]` —— 那是**指针数组**（6 个 `char *` 的数组），完全另一回事
- ❌ 对 `q` 直接 `q[i]` —— 那等价 `*(q+i)`，跳到"下一个数组"，不是"下一个字符"

> 额外提醒：`arr` 和 `&arr` 打印出来**数值可能完全一样**，但类型不同，这就是很多人误以为"一样"的根源。数值一样 ≠ 类型一样 ≠ 步长一样。

## 第 3 章　指针变量 vs 指针指向的数据：两层权限

### ① 一句话结论

看到一句 `char *str = "hello";`，脑子里必须**立刻拆成两层**：

| 层级 | 是什么 | 在哪 | 能不能改 |
|---|---|---|---|
| 第 1 层 | `str` 这个**指针变量本身**，里面存的是一个地址 | 栈 | ✅ 可以改（换成别的地址） |
| 第 2 层 | `str` **指向的那块内存里的内容** | `.rodata` 只读段 | ❌ 不能改 |

### ② 为什么

`str` 是栈上的一个普通变量，它的值是一个数字（地址）。给 `str` 赋值 = 改这个数字 = 让它指向别处，完全合法。

但 `"hello"` 这串字符存放在 `.rodata`（只读常量段），页面权限被标记为**只读**，CPU 写入时会触发内存保护 → 段错误（Segmentation fault）。

### ③ 代码例子

```c
#include <stdio.h>

int main(void)
{
    char *str = "hello";

    printf("改指针前的字符串: %s\n", str);

    str = "world";          // ✅ 第 1 层：改指针指向
    printf("改指针后: %s\n", str);

    // str[0] = 'X';        // ❌ 第 2 层：改只读区内容 → 运行时崩溃
    return 0;
}
```

对比组：

```c
char arr[] = "hello";
arr[0] = 'X';       // ✅ 合法，arr 是栈上的副本
printf("%s\n", arr); // Xello
```

### ④ 四写法权限总表（背下来）

| 写法 | 指针变量（存地址） | 指向内容 | 说明 |
|---|---|---|---|
| `char *s = "hi";` | ✅ 可改指向 | ❌ 不可写内容 | 指向只读字面量 |
| `char s[] = "hi";` | ❌ 数组名不能整体赋值 | ✅ 可写内容 | 栈上副本 |
| `static char s[] = "hi";` | ❌ 同上 | ✅ 可写内容 | 在 `.data` |
| `char *s = malloc(10);` | ✅ 可改指向 | ✅ 可写内容 | 在堆上 |
| `const char *s = "hi";` | ✅ 可改指向 | ❌ 不可写 | const 语义一致 |

### ⑤ 易错点

- ❌ 以为 `char *p = "abc"` 和 `char p[] = "abc"` 只差个名字 —— 差的是**内存归属**，一个在只读段，一个在栈
- ❌ 以为 `const char *p` 加的 `const` 在"禁止改指针" —— 它禁的是**改内容**；`p = "xyz"` 依然合法

# 第二部分　下标与解引用

## 第 4 章　`chs1[i]`、`*(chs1+i)`、`&chs1[i]` 三者的等价链

### ① 一句话结论

```
chs1[i]   ==  *(chs1 + i)       → 第 i 个元素的「值」
&chs1[i]  ==  chs1 + i          → 第 i 个元素的「地址」
```

### ② 为什么

C 标准明确规定：`E1[E2]` 等价于 `(*((E1) + (E2)))`。
所以 `chs1[i]` 天生就是 `*(chs1 + i)`。

而 `&chs1[i]` 展开就是 `&(*(chs1 + i))`。
对同一个地址先解引用再取地址，两个操作互相抵消 → 回到 `chs1 + i`。

```
&( * (chs1 + i) )   →   解引用和取地址抵消   →   chs1 + i
      ↑   ↑
      └───┴── 相抵消
```

### ③ 代码例子

```c
#include <stdio.h>

int main(void)
{
    char *chs1 = "hello";

    for (int i = 0; i < 5; i++)
    {
        printf("i=%d  值:%c   值形式:%c   地址:%p\n",
               i, chs1[i], *(chs1 + i), (void *)&chs1[i]);
    }

    // 两个易混地址，分开打印
    printf("\nchs1         (指针里存的地址，即 'h' 的地址): %p\n", (void *)chs1);
    printf("&chs1        (指针变量自己的栈地址):          %p\n", (void *)&chs1);
    printf("&chs1[0]     (第 0 个字符的地址):             %p\n", (void *)&chs1[0]);
    return 0;
}
```

### ④ 注意：`chs1` 与 `&chs1` 完全不同

```
栈： [ chs1 ] = 0x404000  ──→  .rodata: h e l l o \0

chs1     → 0x404000       （盒子里的内容：'h' 的地址）
&chs1    → 0x7ffe1234     （盒子的门牌号：这个指针变量本身在栈上的地址）
&chs1[0] → 0x404000       （和 chs1 相同）
```

### ⑤ 易错点

- ❌ 把 `chs1` 当成"指针变量的内存地址"。**`chs1` 是它存的值，`&chs1` 才是它自己的地址。**
- ❌ `&chs1[0]` 写成 `&chs1 + 0` —— 前者是 char 地址，后者是指针变量的地址再 +0，差 8 字节量级

## 第 5 章　`&(*q)[i]` 为什么要加括号

### ① 一句话结论

```
&(*q)[i]  ==  (*q) + i      // 取第 i 个字符的地址，步长 +1
q + i                       // 跳到第 i 个数组，步长 +6 —— 完全不同
```

`*q` 一旦解引用，**类型就从 `char (*)[6]` 降级成 `char *`**，后面的加法就变回按字节算。

### ② 为什么（优先级是关键）

优先级顺序：`[]` 高于 `*` 高于 `&`

```c
&(*q)[i]
```
1. 先算括号里 `(*q)` → 得到数组本身，退化为 `char *`
2. 再算 `[i]` → 第 i 个字符
3. 最后 `&` → 这个字符的地址

如果写成 `&*q[i]`：
1. 先算 `q[i]` → `*(q + i)` → 跳到**下一个数组**（+6）
2. 再 `*` → 解引用那个数组
3. 再 `&` → 取地址
→ 结果是一个**越界的数组地址**，逻辑全错。

### ③ 代码例子

```c
#include <stdio.h>

int main(void)
{
    char arr[] = "hello";
    char (*q)[6] = &arr;

    printf("q      = %p\n", (void *)q);
    printf("q+1    = %p   ← 跳了 6 字节\n", (void *)(q + 1));
    printf("(*q)+1 = %p   ← 跳了 1 字节\n", (void *)((*q) + 1));

    for (int i = 0; i < 5; i++)
        printf("&(*q)[%d] = %p,  值 = %c\n",
               i, (void *)&(*q)[i], (*q)[i]);
    return 0;
}
```

### ④ 型别变化一览

| 表达式 | 类型 | 含义 | `+1` 步长 |
|---|---|---|---|
| `q` | `char (*)[6]` | 指向整个数组 | +6 |
| `*q` | `char *`（退化） | 首字符指针 | +1 |
| `q + 1` | `char (*)[6]` | 下一个数组（越界） | +6 |
| `(*q) + 1` | `char *` | 第 2 个字符 | +1 |
| `&(*q)[i]` | `char *` | 第 i 字符地址 | +1 |

### ⑤ 易错点（高频）

- ❌ `&*q[i]` —— 优先级陷阱
- ❌ `&q[i]` —— 同上，`[]` 先结合 `q`
- ✅ 正确写法只有一种：`&(*q)[i]`，**括号必须包住 `*q`**

# 第三部分　数组与函数

## 第 6 章　数组传参退化：为什么要额外传 size

### ① 一句话结论

```
数组名传参 → 自动退化为「首元素指针」
void f(int arr[])  ≡  void f(int *arr)
```

因为退化成了指针，所以**函数内部拿不到数组长度**，必须额外传一个 `size` 参数。

### ② 为什么

C 传参是值传递。数组整体太大，复制一次代价太高，所以标准规定：数组名在表达式中（除 `sizeof` 和 `&`）一律转为指向首元素的指针，只传一个地址过去。

后果连锁：
1. 形参只是个指针变量，`sizeof(arr)` = 指针大小（8），不是数组总字节数
2. `arr++` 改的是这个局部副本，**外部数组不受影响**
3. 上下界信息彻底丢失 → 必须由调用方传长度

### ③ 代码例子

```c
#include <stdio.h>

double getAverage(int *arr, int size)
{
    int sum = 0;
    for (int i = 0; i < size; i++)
    {
        printf("arr 当前指向的地址: %p, 值: %d\n", (void *)arr, *arr);
        sum += *arr;
        arr++;                    // 只改副本，指针后移 4 字节
    }
    return (double)sum / size;    // 必须强转，否则整数除法截断
}

int main(void)
{
    int balance[5] = {1000, 2, 3, 17, 50};
    double avg = getAverage(balance, 5);
    printf("Average: %f\n", avg);
    return 0;
}
```

`sizeof` 验证：

```c
void check(int arr[5])
{
    printf("sizeof(arr) = %zu  ← 是 8（指针大小），不是 20\n", sizeof(arr));
}
```

### ④ 三种等价形参写法

```c
void f(int *arr);           // 最直接
void f(int arr[]);          // 语法糖
void f(int arr[100]);       // 依然是指针，100 会被编译器忽略！
```

> 第三个尤其坑：数组长度写死也没用，`sizeof` 还是 8。C 标准直接把它当 `int *`。

### ⑤ 易错点

- ❌ 在函数里靠 `sizeof(arr)/sizeof(arr[0])` 求长度 —— 永远得到 2（8/4），不是真长度
- ❌ 以为 `arr++` 会影响外面的数组 —— 只影响函数内副本
- ❌ `(double)sum / size` 写成 `sum / size` 后再强转 —— 已经截断，强转救不回来
  ```c
  avg = (double)(sum / size);   // ❌ 先整除再转 double，小数丢了
  avg = (double)sum / size;     // ✅ 先转再除
  ```

## 第 7 章　指针函数：返回值是指针的函数

### ① 一句话结论

```c
返回值类型 *函数名(参数列表)
```
**本质是函数**，只是**返回值是一个指针**。

### ② 为什么（和函数指针区分）

| 写法 | 名字 | 谁是指针 | 谁是函数 |
|---|---|---|---|
| `char *f(char *)` | 指针函数 | 返回值是 | `f` 是函数 |
| `char (*p)(char *)` | 函数指针 | `p` 是 | 指向一个函数 |

记忆：**先看名字在哪一边**
- `*` 在函数名右边、贴着类型 → 返回值是指针 → 指针函数
- `*` 和函数名被括号括在一起 → 名字本身是指针 → 函数指针

### ③ 代码例子

```c
#include <stdio.h>
#include <string.h>

char *strLong(char *s1, char *s2)
{
    return strlen(s1) > strlen(s2) ? s1 : s2;
}

int main(void)
{
    char a[30], b[30];
    printf("输入两个字符串：\n");
    scanf("%29s", a);      // ⚠️ 加宽度限制，防止溢出
    scanf("%29s", b);      // ⚠️ 数组名本身就是地址，不要写 &b
    char *longer = strLong(a, b);
    printf("更长的那个：%s\n", longer);
    return 0;
}
```

**这个例子返回为什么安全？** 因为返回的地址指向 `main` 里的数组 `a` / `b`，生命周期属于调用方，函数结束不影响。

### ④ 核心规则：不能返回内部普通局部变量的地址

```c
int *bad(void)
{
    int n = 10;
    return &n;      // ❌ n 在栈帧里，return 后栈帧被回收 → 野指针
}
```

内存视角：

```
调用 bad()：
  ┌──── bad 的栈帧 ────┐
  │  int n = 10        │  ← 地址 0x7ffe5000
  │  返回地址 ...       │
  └────────────────────┘
return 后：
  这块栈空间被标记可复用，n 的内容随时被别人覆盖
  调用方手里的 0x7ffe5000 → 指向垃圾 → 野指针
```

编译器会警告：`warning: function returns address of local variable`

### ⑤ 解决方案：`static`

```c
int *ok(void)
{
    static int n = 100;   // 挪到 .data 静态区
    return &n;            // ✅ 程序结束前一直有效
}
```

`static` 局部变量三个特点：**不在栈**、**全程存活**、**只初始化一次**。

但代价来了 —— **只有一份内存**：

```c
int *get_max(int x, int y)
{
    static int result;
    result = x > y ? x : y;
    return &result;
}

int *p1 = get_max(1, 9);     // result = 9,  p1 → result
int *p2 = get_max(10, 20);   // result = 20, 同一块！
// 现在 *p1 == 20，因为 p1 和 p2 指向同一地址
```

### ⑥ 四种允许返回的来源

| 来源 | 安全？ | 生命周期 |
|---|---|---|
| 调用方传入的指针（如 `strLong`） | ✅ | 由调用方控制 |
| `static` 局部变量 | ✅ | 整个程序，但只有一份 |
| `malloc` 堆内存 | ✅ | 到 `free` 为止，独立 |
| 全局变量 | ✅ | 整个程序，只有一份 |
| 普通局部变量 / 局部数组 | ❌ | 函数退出即销毁 |

### ⑦ 易错点

- ❌ `scanf("%s", &b)` —— 数组名已是地址，多写 `&` 是类型错误（有些编译器只警告）
- ❌ `scanf("%s", a)` 无限宽 —— 输入超长就栈溢出，写 `%29s` 才安全
- ❌ 以为 `static` 能解决"返回多个结果" —— 只有一份，会互相覆盖

## 第 8 章　函数能不能返回数组？5 种写法全对比

### ① 一句话结论

**C 语言不能直接 `return` 一整个数组。**
函数返回类型只能是：基础类型、指针、结构体/联合体。原生数组不行。

```c
int f()[10]  { ... }    // ❌ 语法错误
```

而且 `[]` 只能出现在**变量定义**和**函数形参**两个位置，返回值位置没有这个语法。

### ② 为什么

数组是"一块连续内存区"，不是可复制的值类型（不像结构体）。函数返回值机制要求这个类型能被"搬"进寄存器 / 返回栈位，原生数组过不了这一关。

那怎么办？围绕"内存归谁管"来选方案。

### ③ 五种写法对比

---

#### 方案 1：`static` 局部数组（最初写法）

```c
int *rand_array(void)
{
    static int arr[10];
    for (int i = 0; i < 10; i++)
        arr[i] = rand() % 50;
    return arr;              // arr 退化为 int*
}
```

| 优点 | 缺点 |
|---|---|
| 简单，返回安全 | ⚠️ 全局只有一份，多次调用**覆盖上次结果** |

```c
int *a = rand_array();
int *b = rand_array();      // a 和 b 指向同一块
// 现在看到的 a 内容已经被 b 那次调用重写了
```

---

#### 方案 2：调用方传入数组（工程最推荐）

```c
void rand_array(int arr[], int n)
{
    for (int i = 0; i < n; i++)
        arr[i] = rand() % 50;
}

int main(void)
{
    int buf[10];
    rand_array(buf, 10);
}
```

| 优点 | 缺点 |
|---|---|
| 内存归调用方（栈），互不干扰 | 需要额外传长度 |
| 不需要 free、不需要 static | 返回类型是 void，不能用 `=` 接 |
| 可同时持有任意多组结果 | |

> **工程首选**：职责清晰，函数只负责"填"，内存管理留给调用方。

---

#### 方案 3：`malloc` 堆分配

```c
#include <stdio.h>
#include <stdlib.h>

int *rand_array(int n)
{
    int *arr = malloc(n * sizeof(int));
    if (arr == NULL) { perror("malloc"); exit(EXIT_FAILURE); }
    for (int i = 0; i < n; i++)
        arr[i] = rand() % 50;
    return arr;
}

int main(void)
{
    int *p = rand_array(10);
    for (int i = 0; i < 10; i++)
        printf("%d ", p[i]);
    free(p);              // ⚠️ 必须释放
}
```

| 优点 | 缺点 |
|---|---|
| 每次全新独立内存 | 必须记得 `free`，否则泄漏 |
| 长度可运行时决定 | 出错点多（NULL、重复 free） |

---

#### 方案 4：结构体包裹数组（整体值返回）

```c
typedef struct { int data[10]; } IntArr;

IntArr rand_array(void)
{
    IntArr tmp;
    for (int i = 0; i < 10; i++)
        tmp.data[i] = rand() % 50;
    return tmp;                 // 整个结构体值拷贝返回
}

int main(void)
{
    IntArr r = rand_array();
    for (int i = 0; i < 10; i++)
        printf("%d ", r.data[i]);
}
```

| 优点 | 缺点 |
|---|---|
| 天然"值语义"，每次独立 | 长度写死 |
| 不需要 free 也不需要 static | 大数组拷贝开销高 |

> 原理：结构体是**值类型**，`return tmp` 时编译器把整个结构体拷贝给调用方（或在调用方栈上直接构造，RVO 优化）。

---

#### 方案 5：全局数组（不推荐）

```c
int g_arr[10];

int *rand_array(void)
{
    for (int i = 0; i < 10; i++)
        g_arr[i] = rand() % 50;
    return g_arr;
}
```

毛病同方案 1：只有一份，多次调用互相覆盖；还污染全局命名空间。

---

### ④ 五方案总对比表

| 方案 | 独立内存 | 需要 free | 多次调用覆盖 | 长度可动态 | 推荐度 |
|---|---|---|---|---|---|
| `static` 数组 | ❌ | 不需要 | ✅ 会覆盖 | ❌ | ⭐⭐ |
| 外部传入 | ✅ | 不需要 | ❌ | ✅ | ⭐⭐⭐⭐⭐ |
| `malloc` | ✅ | ✅ 必须 | ❌ | ✅ | ⭐⭐⭐⭐ |
| 结构体 | ✅（拷贝一份） | 不需要 | ❌ | ❌ | ⭐⭐⭐ |
| 全局数组 | ❌ | 不需要 | ✅ | ❌ | ⭐ |

### ⑤ 易错点

- ❌ `int rand_array[]() { ... }` —— 语法不允许
- ❌ `return arr;` 当成"返回整个数组" —— 实际只返回首元素地址
- ❌ 用 `static` 方案后又同时保存两个结果 —— 后一个覆盖前一个
- ❌ `malloc` 后忘记判 NULL、忘记 `free`

## 第 9 章　`int (*f())[10]` 与 `int (*f)[]()` 的区别

### ① 一句话结论

```c
int (*rand_array())[10]     // ✅ 合法：函数返回「数组指针」
int (*rand_array)[]()       // ❌ 非法：语法拼错，没有这种组合
```

再加上一个合法的：

```c
int (*p)()                  // ✅ 合法：函数指针
```

### ② 为什么（螺旋法则一步步读）

```c
int (*rand_array())[10]
```
1. 从名字 `rand_array` 开始
2. 右边是 `()` → **它首先是一个函数**
3. 括号里的 `*` → 函数**返回一个指针**
4. 再右边 `[10]` → 这个指针**指向一个 10 元素的数组**
5. 再往左 `int` → 数组元素是 int

→ 读作：**`rand_array` 是一个函数，返回值类型为 `int (*)[10]`（指向 10 个 int 数组的指针）**

```c
int (*rand_array)[]()
```
1. `(*rand_array)` → `rand_array` **是一个指针**
2. 后面跟着 `[]()` → "数组 + 函数调用"，这个后缀组合不合法
→ 编译器报错

### ③ 代码例子（正确版本）

```c
#include <stdio.h>
#include <stdlib.h>

int (*rand_array(void))[10]
{
    static int arr[10];
    for (int i = 0; i < 10; i++)
        arr[i] = rand() % 50;
    return &arr;                     // ⚠️ &arr 类型是 int (*)[10]
}

int main(void)
{
    int (*p)[10] = rand_array();     // p 是数组指针

    for (int i = 0; i < 10; i++)
        printf("%d ", (*p)[i]);      // ⚠️ 必须 (*p)[i]
    return 0;
}
```

**两个关键点：**
1. `return &arr;` 不能写 `return arr;`
   - `arr` → `int *`
   - `&arr` → `int (*)[10]` ✅
2. 访问元素必须 `(*p)[i]`，不能 `p[i]`（那是"第 i 个数组"）

### ④ 三种写法并排

| 写法 | 名字 | 本质 | `+1` 步长 |
|---|---|---|---|
| `int *f()` | 指针函数 | 函数，返回 `int *` | +4 |
| `int (*f())[10]` | 指针函数 | 函数，返回 `int (*)[10]` | +40 |
| `int (*p)()` | 函数指针 | 指针，指向函数 | —（不能做指针运算） |

### ⑤ 易错点

- ❌ 少写一层括号 `int *f()[10]` —— 编译器理解成"返回指针数组"，而且函数不能返回数组，直接报错
- ❌ `return arr;`（类型不匹配）
- ❌ 用 `p[i]` 访问元素

> 实用建议：这种写法在工程里罕见，符号太绕。日常如果要"返回二维数组"，还是用 `方案 2（外部传入）` 或 `malloc` 更清楚。

# 第四部分　函数指针

## 第 10 章　函数指针：指向函数的指针

### ① 一句话结论

```c
返回值类型 (*指针名)(参数列表);
```
**本质是指针**，里面存的是函数的入口地址。

```c
int (*p)(int, int) = get_sum;    // 括号绝不能省！
```

**省了会怎样？**
```c
int *p(int, int);    // 变成「指针函数」：是函数，返回 int*
```
括号是唯一决定"这是函数指针还是指针函数"的东西。

### ② 为什么（内存角度）

```c
int get_sum(int x, int y) { return x + y; }
```

- 函数本体（机器指令）永远在**代码段 `.text`**
- `get_sum` 这个"名字"在表达式里会转换成**函数入口地址**（一段 `.text` 里的地址）
- 函数指针变量本身是**栈上的一个变量**，里面装这个地址

```
【.text 代码段】                       【main 栈帧】
0x00401050 ─ get_sum 指令起点           ptr_sum：8 字节
             ├ push ebp                └── 存的值 = 0x00401050
             ├ mov eax, ...
             └ ret
```

调用时：从 `ptr_sum` 里取出 `0x00401050` → 跳过去执行 `get_sum` 的指令。

### ③ 代码例子

```c
#include <stdio.h>

int get_sum(int x, int y) { return x + y; }
int get_sub(int x, int y) { return x - y; }

int main(void)
{
    int (*fn)(int, int) = get_sum;      // 参数名可省略：int (*fn)(int,int)

    printf("fn(3,4)     = %d\n", fn(3, 4));        // 语法糖，最简单
    printf("(*fn)(3,4)  = %d\n", (*fn)(3, 4));     // 标准解引用调用

    fn = get_sub;                                    // 指向另一个函数
    printf("切换后 fn(3,4) = %d\n", fn(3, 4));       // -1
    return 0;
}
```

### ④ 为什么要用它（价值在哪）

不做函数指针也能写代码，那它存在的意义是什么？三个真实用途：

1. **回调函数**：把"做什么"作为参数传给别的函数（`qsort` 的比较函数就是）
2. **表驱动 / 状态机**：用数组存一堆函数指针，按索引分发
3. **运行时切换**：同一套接口，指向不同实现（比如 `fn = get_add` / `fn = get_sub`）

示例（`qsort`）：

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_int(const void *a, const void *b)
{
    return *(const int *)a - *(const int *)b;
}

int main(void)
{
    int a[5] = {5, 3, 1, 4, 2};
    qsort(a, 5, sizeof(int), cmp_int);    // cmp_int 就是回调
    for (int i = 0; i < 5; i++) printf("%d ", a[i]);
}
```

### ⑤ 易错点

- ❌ `int *p(int, int)` —— 少了括号，是函数不是指针
- ❌ 用 `(*p)()` 觉得比 `p()` 更"正确" —— 两者完全等价，`p()` 是标准语法糖
- ❌ 对函数指针做 `p + 1` —— 标准禁止对函数指针做算术运算

---

## 第 11 章　`get_sum`、`&get_sum`、`*get_sum` 为什么一样

### ① 一句话结论

```c
get_sum  ==  &get_sum  ==  *get_sum  ==  **get_sum  ==  ...
```

全是同一个值：**函数的入口地址**。套多少层 `*` 都不变。

### ② 为什么（三条函数专属规则）

| 规则 | 内容 |
|---|---|
| 规则 1 | 函数名在表达式中**隐式转换**为函数入口地址（类似数组名退化） |
| 规则 2 | `&函数名` 得到的结果和 `函数名` 一样（对普通变量不成立） |
| 规则 3 | 对函数指针解引用 `*`，得到的仍然是这个函数本身，值仍是入口地址 |

理解规则 3 的关键：**函数不是"某个内存格子里存着一个值"那样的东西**。函数是一整段指令，"拿到这个函数"就等于"拿到这段指令的入口地址"。所以 `*` 在这里没有"取出数据"的作用，只是"间接寻址到同一个点"。

对比普通指针：

```c
int a = 10;
int *p = &a;
a  !=  &a          // 值 10 vs 地址；不等
*p ==  a           // 解引用得到值 10
```

### ③ 代码例子（打印验证）

```c
#include <stdio.h>

int get_sum(int x, int y) { return x + y; }

int main(void)
{
    int (*fn)(int, int) = get_sum;

    printf("get_sum   = %p\n", (void *)get_sum);
    printf("&get_sum  = %p\n", (void *)&get_sum);
    printf("*get_sum  = %p\n", (void *)(*get_sum));
    printf("**get_sum = %p\n", (void *)(**get_sum));

    printf("fn        = %p   ← 存的值（函数入口）\n", (void *)fn);
    printf("&fn       = %p   ← 指针变量自己的栈地址\n", (void *)&fn);
    printf("*fn       = %p\n", (void *)(*fn));
    return 0;
}
```

输出特征：前四行全部一样，`fn` 也和它们一样，只有 `&fn` 不同。

### ④ 一个必须分清的三组地址

```
                  值（里面装的）              自己的地址
普通变量 a   :    a = 10            &a = 栈地址
普通指针 p   :    p = &a            &p = 栈地址
函数名       :    get_sum = 入口地址  &get_sum = 入口地址  ← 相同！
函数指针 fn  :    fn = 入口地址      &fn = 栈地址            ← 不同！
```

一句话：**函数名取地址等于它自己；函数指针取地址是它自己在栈上的门牌号。**

### ⑤ 易错点

- ❌ 以为 `&get_sum` 是"函数名这个变量在内存里的位置" —— 函数名不是变量，不存在"函数名变量"
- ❌ 以为 `*fn` 是"取出函数返回值" —— 它只是拿到函数本身
- ❌ 打印时忘加 `(void *)` 强制转换 —— 有些平台 `%p` 对函数指针会警告

# 第五部分　内存模型

## 第 12 章　进程内存五大区完整图

### ① 一句话结论

一个 C 程序跑起来，用户态虚拟地址空间从低到高大致这么排：

```
低地址 ────────────────────────────────────→ 高地址

[ .text ]  [ .rodata ]  [ .data ]  [ .bss ]  [... 堆 ↓↑ ...]  [ 栈 ]
  代码       只读常量     已初始化     未初始化     malloc 区       局部变量
                          全局/静态    全局/静态
```

### ② 为什么（每区管什么）

```
┌─────────────────────────────────────────────────┐ 高地址
│  内核空间（用户程序无权直接访问）                   │
├─────────────────────────────────────────────────┤
│  🌊 栈 Stack  ↓ 向下生长                          │
│     ├─ 函数调用时的栈帧                           │
│     │   ├─ 形参                                   │
│     │   ├─ 局部变量                                │
│     │   ├─ 局部数组                                │
│     │   ├─ 函数指针变量                            │
│     │   └─ 返回地址（回到调用者的位置）            │
│     ✅ 进入函数开辟，return 立刻整体回收            │
│     ❌ 返回这里的地址 = 野指针                     │
├─────────────────────────────────────────────────┤
│              （空闲间隙，防栈堆相撞）               │
├─────────────────────────────────────────────────┤
│  📦 堆 Heap  ↑ 向上生长                           │
│     malloc / calloc / realloc 申请的内存           │
│     ✅ 你手动 free 才释放                          │
│     ✅ 可跨函数长期使用                            │
│     ❌ 忘 free → 内存泄漏                          │
├─────────────────────────────────────────────────┤
│  🗂 静态存储区                                     │
│     ├─ .data ：已初始化的全局 / static 变量          │
│     │    static int arr[10] = {1,2,3};            │
│     │    int g = 100;                              │
│     └─ .bss  ：未初始化的全局 / static（启动清零）   │
│          static int n;                             │
│          int g2;                                   │
│     ✅ static 局部变量在这，不在栈！                 │
│     ✅ 程序全程存活                                │
│     ⚠️ 所有使用点共用同一份                         │
├─────────────────────────────────────────────────┤
│  🔒 只读常量段 .rodata                            │
│     字符串字面量 "hello"、const 常量                │
│     ❌ 写入触发段错误                              │
├─────────────────────────────────────────────────┤
│  ⚙ 代码段 .text                                   │
│     所有函数的机器指令：main / get_sum / ...        │
│     ✅ 函数指针存的就是这里的地址                   │
│     ✅ 只读，CPU 从这里取指令执行                   │
└─────────────────────────────────────────────────┘ 低地址
```

### ③ 常见东西归属表（这张表必须背）

| 东西 | 所在区域 | 生命周期 | 可写 |
|---|---|---|---|
| 普通局部变量 `int x;` | 栈 | 函数调用期间 | ✅ |
| 局部数组 `int a[10];` | 栈 | 函数调用期间 | ✅ |
| `static` 局部变量 | 静态区 | 整个程序 | ✅ |
| 全局变量 | 静态区 | 整个程序 | ✅ |
| `malloc` 出来的内存 | 堆 | malloc → free | ✅ |
| 字符串字面量 `"abc"` | `.rodata` | 整个程序 | ❌ |
| `const` 常量 | `.rodata` | 整个程序 | ❌ |
| 函数指令本体 | `.text` | 整个程序 | ❌ |
| 函数指针变量本身 | 栈 | 所在函数期间 | ✅（可改指向） |

### ④ 最关键的一条认知

> **指针变量本身 和 它指向的东西，往往不在同一块内存。**

```c
char *s = "hello";              // s 在栈；"hello" 在 .rodata
int  *p = malloc(10*sizeof(int));// p 在栈；数组本体在堆
int (*fp)(int,int) = get_sum;    // fp 在栈；get_sum 指令在 .text
static int arr[10];              // arr 在 .data（不在栈！）
```

这个认知一旦建立，很多问题自动解决：
- 为什么 `char *p = "abc"` 不能改 → 副本在 rodata
- 为什么返回局部变量地址危险 → 栈帧回收
- 为什么 `static` 能救 → 挪到静态区

### ⑤ 单个栈帧内部长什么样

```
main 的栈帧（简化）
┌───────────────────────────┐  ← 高地址（栈帧顶部接近起点）
│ 返回地址（返回 main 的上级） │
│ 保存的 ebp/rbp             │
│ int x                      │  ← 局部变量 1
│ int y                      │  ← 局部变量 2
│ int (*fn)(int,int)         │  ← 函数指针变量
└───────────────────────────┘  ← 低地址（栈向下生长，这是栈帧"底部"）
```

每调用一层函数，就压一个这样的栈帧；`return` 时，栈指针 (rsp) 直接挪回去 —— **"回收"不是删数据，只是把这块内存标记为可复用**。原来的数据还留在那，但随时可能被下一个函数覆盖。这就是野指针的根源。

### ⑥ 易错点

- ❌ 以为"函数回收时把内存清零了" —— 没有，只是栈指针回退，数据残留
- ❌ 以为 `static` 局部变量"地址不变所以安全" —— 地址确实不变，但只有一份，会被覆盖
- ❌ 以为 `.bss` 的"未初始化"是垃圾值 —— 进程启动时被操作系统清零，所以是 0

## 第 13 章　大段与小段：两个完全不同的概念

### ① 一句话结论

| 名词 | 是什么 | 关键特征 |
|---|---|---|
| **大段**（逻辑段 / segment） | `.text / .rodata / .data / .bss / heap / stack` | 按**用途**划分，大小不固定，权限不同 |
| **小段**（paragraph / 小节） | 内存的**对齐格子** | **固定 16 字节**，起始地址 `% 16 == 0` |
| **硬件段**（8086 CS/DS/SS/ES） | 早期 CPU 的段寄存器 | 每段最大 **64KB**，段基址必须落在小段边界 |

**三套体系别混：大段是"功能划分"，小段是"对齐单位"，硬件段是"8086 寻址机制"。**

### ② 为什么有两个概念

- 操作系统 / 链接器关心的是"哪块内存放代码、哪块放数据、各给什么权限" → 这是**大段**
- CPU / 内存总线关心的是"最小对齐粒度、访问边界" → 这是**小段（16 字节）**

内存访问按 16 字节对齐能提高效率，所以所有大段的起点、`malloc` 返回的地址，都会对齐到至少 16 字节。

### ③ 图示

```
小段的切分（固定 16B）：
  0x00000 ~ 0x0000F   ← 小段 0
  0x00010 ~ 0x0001F   ← 小段 1
  0x00020 ~ 0x0002F   ← 小段 2
  0x00030 ~ 0x0003F   ← 小段 3
  ...
  每个小段首地址末位十六进制 = 0
```

大段套在小段里：

```
┌────────────────────────────────┐ 高地址
│  栈                            │  ← 大段：起点对齐 16B
├────────────────────────────────┤
│  空闲                          │
├────────────────────────────────┤
│  堆                            │  ← 大段：起点对齐 16B
├────────────────────────────────┤
│  .data / .bss                  │  ← 大段
├────────────────────────────────┤
│  .rodata                       │  ← 大段
├────────────────────────────────┤
│  .text                         │  ← 大段
└────────────────────────────────┘ 低地址
       ↑ 所有这些起点都踩在「小段」的格子线上
```

### ④ 8086 硬件段（如果考微机原理，必须知道）

```
物理地址 = 段基址 × 16 + 偏移地址（offset）

CS:IP  → 取下一条指令
DS:SI  → 取数据
SS:SP  → 取栈
```

- 段基址存在段寄存器里，只有 16 位
- `× 16`（左移 4 位）= 段基址的最低位是 0 = 对齐到小段边界
- 每段最多覆盖 64KB（16 位偏移能表示的范围）

### ⑤ 易错点（超级高频）

- ❌ 把"大端小端"和"大段小段"混为一谈 —— **完全两回事**
  - 大端小端 = 一个数字的**字节顺序**
  - 大段小段 = 内存的**功能分区 / 对齐单位**
- ❌ 以为"小段"是"小的代码段" —— 它是**对齐单位**，不关内容
- ❌ 以为小段大小可变 —— 固定 16 字节

## 第 14 章　大端与小端：字节在内存里的顺序

### ① 一句话结论

**只针对多字节类型**（`int` / `long` / `float` / `double`），决定"一个数字的各个字节在内存里谁在前"。

```
int num = 0x12345678;
字节拆分：      高字节              低字节
              0x12   0x34   0x56   0x78
```

| 模式 | 规则 | 低地址里放 |
|---|---|---|
| **小端** Little-Endian | 低字节 → 低地址 | `0x78` |
| **大端** Big-Endian | 高字节 → 低地址 | `0x12` |

### ② 为什么会有两种

- 小端有利于**数值运算**（低字节在低地址，做加法/进位时低地址先算，效率高）
- 大端符合**人的阅读习惯**（从左到右读，和写数字顺序一样）

历史遗留 + 硬件设计取舍结果。x86/x86-64（Intel、AMD）全用小端；网络协议统一规定用大端（"网络字节序"）。

### ③ 图示对比

```
数值：0x12345678

小端（x86、你的电脑）：
地址  100     101     102     103
内存  0x78    0x56    0x34    0x12
      ↑低地址里放最低字节

大端（网络序）：
地址  100     101     102     103
内存  0x12    0x34    0x56    0x78
      ↑低地址里放最高字节
```

### ④ 判断本机大小端（两种写法）

**写法 A：指针法**

```c
#include <stdio.h>

int main(void)
{
    int n = 1;                      // 内存：0x00 00 00 01
    char *p = (char *)&n;           // 看第一个字节
    if (*p == 1)
        printf("小端\n");            // 第一个字节是 0x01 → 低字节在低地址
    else
        printf("大端\n");            // 第一个字节是 0x00
    return 0;
}
```

**写法 B：联合体法（面试更常见）**

```c
#include <stdio.h>

int main(void)
{
    union {
        int  i;
        char c[4];
    } u;
    u.i = 1;
    if (u.c[0] == 1)
        printf("小端\n");
    else
        printf("大端\n");
    return 0;
}
```

> 联合体所有成员共用同一块内存，改 `i` 会影响 `c[]`，所以看 `c[0]` 就能窥见最低地址上的字节。

### ⑤ 网络编程转换

```c
#include <arpa/inet.h>

uint32_t htonl(uint32_t hostlong);   // host to network long（大端）
uint16_t htons(uint16_t hostshort);
uint32_t ntohl(uint32_t netlong);    // network to host long
uint16_t ntohs(uint16_t netshort);
```

电脑是小端 → `htonl` 会帮你翻转字节；电脑本来就是大端 → 这几个函数是空操作。

### ⑥ 易错点

- ❌ 以为 `char` 也有大小端 —— 单字节无所谓端
- ❌ 把"大端小端"和"大段小段"混起来 —— 见上一章
- ❌ 以为 float 没这个问题 —— float 也按字节存，一样有大小端
- ❌ 以为小端就是"反着存" —— 是**字节**反着排，不是位反着排

## 第 15 章　数组到底存在哪？压栈还是不在栈

### ① 一句话结论

> **"数组"这个身份不决定它在哪；决定它位置的是"它在哪定义"。**

| 定义方式 | 数组本体位置 |
|---|---|
| 函数内 `int a[10];` | **栈**（压栈） |
| 函数内 `static int a[10];` | 静态区（**不在栈！**） |
| 全局 `int a[10];` | 静态区 |
| `int *p = malloc(...)` | `p` 在栈，**数组本体在堆** |
| `char buf[] = "abc";` | 栈（从 rodata 拷一份过来） |
| `char *p = "abc";` | `p` 在栈，**"abc" 在 `.rodata`** |

### ② 为什么

数组是"一块连续同类型元素的内存"，它本身没有"我要住哪"的属性。编译器/运行时根据**定义位置**决定分配在哪。

### ③ 代码例子（一次看全）

```c
#include <stdio.h>
#include <stdlib.h>

int g[5];                          // 全局 → 静态区

void f(void)
{
    int   stack_arr[5];            // 栈
    static int static_arr[5];      // 静态区
    int  *heap_arr = malloc(5 * sizeof(int));   // heap_arr 在栈，数组本体在堆
    char  buf[] = "abc";           // buf 在栈
    char *lit  = "abc";            // lit 在栈，"abc" 在 .rodata

    printf("stack_arr   = %p\n", (void *)stack_arr);    // 栈区地址范围
    printf("static_arr  = %p\n", (void *)static_arr);   // 静态区地址范围
    printf("heap_arr    = %p\n", (void *)heap_arr);     // 堆地址范围
    printf("buf         = %p\n", (void *)buf);          // 栈
    printf("lit         = %p\n", (void *)lit);          // .rodata
    printf("g           = %p\n", (void *)g);            // 静态区

    free(heap_arr);
}
```

典型输出特征（地址在典型 Linux 下）：
- 栈地址：`0x7ffd...` 或 `0x7fff...`（很高）
- 堆地址：`0x55...` 或者 `0x602000...`（中等）
- `.rodata` / `.text`：`0x40...` / `0x55...`（很低）
- 静态区：介于低地址和堆之间

> 这里各段地址看的是**趋势和关系**，不同系统和 ASLR 下具体数值会变。

### ④ 局部数组的最大坑

```c
int *get_arr(void)
{
    int arr[10];
    arr[0] = 1;
    return arr;        // ❌ 返回栈地址，函数退出即失效
}
```

内存时间轴：

```
T1  f() 被调用：栈上开辟 arr[10]，写入数据
T2  return：栈指针回退，arr 那块被标记"可复用"
T3  调用方拿到指针 → 此时缓冲区里写入新数据 → arr 原位置被覆盖
T4  你去读 *p → 读到垃圾值
```

> 只有在返回的那一刻还"看起来对"，一旦再调用任何一个函数，数据就可能被冲掉。这就是"有时能跑，有时崩溃"的原因。

### ⑤ 结论汇总

- 只要是**数组**，元素一定**连续存放**
- 位置由定义点决定：栈 / 静态区 / 堆 / 只读段
- 想在函数间安全传递"一整块数组" → 用**调用方传入**或**`malloc`**

### ⑥ 易错点

- ❌ 以为"数组就是栈上的" —— 有 `static` / 全局 / `malloc` 版本
- ❌ 以为 `char buf[] = "abc"` 里的 `"abc"` 还在 rodata 里指着 —— 它已经**拷贝**到栈上
- ❌ 以为 `sizeof(arr)` 在函数里能拿到长度 —— 见第 6 章

# 第六部分　字符串

## 第 16 章　字符串与字符数组：`\0` 到底是什么

### ① 一句话结论

```
C 字符串  =  以 '\0'（数值 0）结尾的 char 数组
```

但反过来**不成立**：
```
char 数组  ≠  一定是字符串      （没有 '\0' 就只是普通数组）
```

### ② 为什么需要 `\0`

C 的字符串函数（`strlen`、`strcpy`、`printf("%s")`）**除了首地址外拿不到任何长度信息**。
所以全部靠"一直往后读，直到遇到 `\0` 停下"来确定边界。

没有 `\0` → 它们只能一路往下读，冲出数组 → 读到别的变量的内存。

```
char arr[3] = {'a','b','c'};      // 无 '\0'
printf("%s", arr);
     ↓
读出：a b c [后面内存里的垃圾...] 一直到偶然遇到一个 0x00
```

### ③ 四种情况逐一说明

**情况 1：普通字符数组（不是字符串）**

```c
char arr[3] = {'a', 'b', 'c'};
// 内存：a b c，无 '\0'
// %s / strlen 都会越界 → 未定义行为
```

**情况 2：省去长度 → 自动补 `\0`（是字符串）**

```c
char arr[] = "abc";
// 内存：a b c \0    长度 4
sizeof(arr) == 4;      // 含末尾 \0
strlen(arr) == 3;      // 不含
```

**情况 3：手动补 `\0`（也是字符串）**

```c
char arr[4] = {'a', 'b', 'c', '\0'};
```

**情况 4：非 char 数组（与 `\0` 无关）**

```c
int  a[5] = {1,2,3,4,5};
double b[3];
// 它们的长度由「元素个数 × sizeof(元素)」给出，不靠结束标记
```

### ④ 三个极易考的对比

```c
char s1[] = "hello";
// 大小 6，内容 h e l l o \0，是字符串 ✅

char s2[5] = {'h','e','l','l','o'};
// 大小 5，内容 h e l l o（无 \0），只是字符数组 ❌

char s3[10] = {'h','i'};
// 大小 10，内容 h i \0 \0 \0 \0 \0 \0 \0 \0，是字符串 ✅
// 剩余元素自动零初始化
```

`s3` 为什么是字符串？因为**部分初始化时，剩下的元素被零初始化**，`s3[2]` 天然就是 0。

### ⑤ `sizeof` 与 `strlen` 对比表

| | `sizeof` | `strlen` |
|---|---|---|
| 计算时机 | 编译期（数组名不退化时） | 运行期 |
| 是否算 `\0` | ✅ 算 | ❌ 不算 |
| 作用于指针时 | 返回指针大小（8） | 正常（读到 `\0`） |
| 作用 `char arr[] = "abc"` | 4 | 3 |

```c
char arr[] = "abc";
char *p = arr;
sizeof(arr);    // 4
sizeof(p);      // 8（指针大小，不是 4）
strlen(p);      // 3
```

### ⑥ 易错点

- ❌ `'\0'` 和 `'0'` 搞混
  - `'\0'` = ASCII **0**，空字符，数值 0
  - `'0'` = ASCII **48**，字符 `'0'`，是**可打印的字符**
  - `strlen("0")` 等于 1（一个字符 `'0'`）
- ❌ 初始化用 `char arr[3] = "abc"` —— **编译错误**，`"abc"` 是 4 个字节（含 `\0`），放不进 3 格
- ❌ `sizeof` 用在指针上还以为是数组长度

## 第 17 章　`char arr[]` 能改，`char *p` 不能改（核心原因）

### ① 一句话结论

```c
char arr[] = "hello";    // ✅ arr[0] = 'X'  合法
char *p   = "hello";     // ❌ p[0] = 'X'    崩溃
```

**唯一原因：`arr` 是栈上的副本，`p` 指向 `.rodata` 里的原件。**

### ② 为什么（执行流程对比）

**`char arr[] = "hello";` 的执行过程**
1. `"hello\0"` 原件在 `.rodata`
2. 编译器生成"**拷贝**"指令：把 6 字节从 rodata 复制到栈上的 `arr`
3. `arr` 是栈上数组，可写
4. `arr[0] = 'X'` 改的是栈上的副本 → ✅

内存态：
```
.rodata : h e l l o \0         （原件，只读，但已无引用）
栈     : arr = [h][e][l][l][o][\0]   ← 副本，可写
```

**`char *p = "hello";` 的执行过程**
1. `"hello\0"` 在 `.rodata`
2. 编译器只做一件事：把 rodata 那个地址装进 `p`
3. `p` 是栈上一个指针变量，指向只读区
4. `p[0] = 'X'` 写入只读页 → 内存保护机制触发 → **Segmentation fault**

内存态：
```
栈     : p = 0x404000  ───┐
                          ↓
.rodata: h e l l o \0    （因为只读，写入失败）
```

### ③ 三个变种的权限

```c
char arr[] = "hello";              // 栈副本，可写 ✅
static char sand[] = "hello";      // 静态区副本，可写 ✅
const char *p = "hello";           // 指向 rodata，不可写 ❌
char *q = "hello";                 // 同上，不可写 ❌（但编译器不警告）
```

**为什么 `char *p = "hello"` 还能编译通过？**
历史原因：早期 C 没有 `const` 概念，`char *` 和 `const char *` 是同一类型。字符串字面量是"实在没法避免"要指向 rodata 的情况，所以标准留了个口子（在 C++ 里这个写法直接报错 —— 因为 C++ 的 `"hello"` 类型是 `const char*`）。

### ④ 一句话口诀

> `[]` → **开辟自己的空间 + 复制一份** → 能改
> `*` → **只借了个地址** → 改的是人家原件 → 不能改

### ⑤ 想安全又想用指针怎么办

**办法 1：加 `const`（推荐）**

```c
const char *p = "hello";   // p[0] = 'X' → 编译期报错，安全多了
```

**办法 2：指向栈数组**

```c
char buf[] = "hello";
char *p = buf;             // p 指向栈，p[0] = 'X' 合法
```

**办法 3：堆上拷贝**

```c
char *p = malloc(6);
strcpy(p, "hello");
p[0] = 'X';                // ✅ 改的是堆
free(p);
```

### ⑥ 易错点

- ❌ 把 `char *p = "abc"` 改成 `p[0]='X'`，以为"和数组一样" —— 这是**最常见的线上崩溃源**
- ❌ 以为加了 `const` 就能挡住一切 —— `const` 只防"通过这个指针写"，不防别的别名指针去写
- ❌ 以为 `printf("%s", "hello")` 里什么"只是临时变量" —— 字符串字面量本身就在 rodata

## 第 18 章　`char (*p)[]` 合法吗？里面的值能改吗

### ① 一句话结论

**语法合法**，它是"指向一个 char 数组的指针"（数组指针）。
**能不能改里面的值，不取决于这个指针写法，取决于它指向的内存在哪。**

```c
char (*p)[10];    // 指向 char[10]（最常用）
char (*p)[];      // 指向长度未知的 char 数组（不完整类型）
```

### ② 为什么

- `char (*p)[10]` 是**完整类型**：指向一个"10 个 char"的数组指针，可以正常使用
- `char (*p)[]` 是**不完整类型**：长度未知，编译器算不了 `sizeof(*p)`，也无法在 `p+1` 时确定步长

所以现实中几乎只用带长度的版本，或者直接 `char *`。

### ③ 代码例子（固定长度版）

```c
#include <stdio.h>

int main(void)
{
    char buf[10] = "hi";
    char (*p)[10] = &buf;         // ⚠️ &buf，不是 buf

    printf("buf        = %p\n", (void *)buf);      // 首字符地址
    printf("&buf       = %p   ← 数值可能相同\n", (void *)&buf);
    printf("p          = %p\n", (void *)p);
    printf("p + 1      = %p   ← +10\n", (void *)(p + 1));

    printf("(*p)[0]    = %c\n", (*p)[0]);           // h
    (*p)[0] = 'H';                                  // ✅ buf 在栈，可写
    printf("改后 buf   = %s\n", buf);               // Hi

    return 0;
}
```

### ④ 可改性判定表

| `p` 指向的是什么 | 能不能改 `(*p)[i]` |
|---|---|
| 栈上数组 `char buf[]` | ✅ |
| `static` / 全局数组 | ✅ |
| `malloc` 堆内存 | ✅（需显式类型转换） |
| `"hello"` 字面量 | ❌ 类型不匹配，强转后写会崩 |

```c
char (*p)[] = "hello";                  // ❌ 编译错误
// "hello" 在表达式里是 char*，类型不对

char (*p)[] = (char (*)[]) "hello";     // ⚠️ 强转能通过
// (*p)[0] = 'X';  → 运行时：段错误
```

### ⑤ 三个易混写法对照

```c
char  *p[5];      // 数组，5 个元素，每个是 char*    → 指针数组
char (*p)[5];     // 指针，指向一个 char[5]          → 数组指针
char **p;         // 指针，指向 char*（二级指针）
char  p[];        // 非法（块作用域下不允许不完整数组）
```

记忆法：看 `[]` 和 `*` 谁先结合
- `[]` 先结合名字 → 名字是数组（`char *p[5]` 是数组）
- 括号打断 → 名字是指针（`char (*p)[5]` 是指针）

### ⑥ 易错点

- ❌ `char (*p)[10] = buf;` —— 应该 `&buf`
- ❌ 用 `p[i]` 取字符 —— 应该 `(*p)[i]`
- ❌ 以为写了 `char (*p)[]` 就一定"只能读" —— 完全没有这回事

# 第七部分　文件 I/O

## 第 19 章　`fopen` 六种模式全对照

### ① 一句话结论

```
r  只读，没有就失败
w  只写，存在就清空
a  只追加，写在末尾
r+ 读写，不清空，文件必须存在
w+ 读写，打开直接清空
a+ 读写，读从头，写必追加
```

### ② 完整对照表

| 模式 | 可读 | 可写 | 文件不存在时 | 文件存在时 | 初始读写位置 |
|---|---|---|---|---|---|
| `"r"` | ✅ | ❌ | ❌ 返回 NULL | ✅ 保留内容 | 开头 |
| `"w"` | ❌ | ✅ | ✅ 新建 | ⚠️ **清空（截断为 0）** | 开头 |
| `"a"` | ❌ | ✅ | ✅ 新建 | ✅ 保留内容 | 末尾（写总在尾部） |
| `"r+"` | ✅ | ✅ | ❌ 返回 NULL | ✅ 保留内容 | 开头 |
| `"w+"` | ✅ | ✅ | ✅ 新建 | ⚠️ **清空** | 开头 |
| `"a+"` | ✅ | ✅ | ✅ 新建 | ✅ 保留内容 | 读：开头；写：末尾 |

### ③ "加号"到底代表什么

**`+` 的唯一含义：从单向变成双向（同时可读可写）。**

常见误解：
- ❌ 以为 `+` 是"追加" —— **追加是字母 `a`**，不是加号
- ❌ 以为 `w+` 和 `r+` 差不多 —— `w+` 会**直接清空**

### ④ 三组必考对比 + 场景

**场景 1：只想读，文件必须存在**
```c
FILE *fp = fopen("data.txt", "r");
if (!fp) { perror("open"); return 1; }   // 用 r 必须判空
```

**场景 2：要写入新内容，覆盖旧文件**
```c
FILE *fp = fopen("out.txt", "w");        // 文件不存在就新建
```

**场景 3：日志追加**
```c
FILE *fp = fopen("log.txt", "a");        // 老内容保留，新内容写在末尾
```

**场景 4：既要读又要写，但保留原内容**
```c
FILE *fp = fopen("data.txt", "r+");      // 文件必须存在，不清空
```
> 危险点：`r+` 写入会**覆盖**当前位置的字节，新内容比旧内容短时，尾部残留旧数据。

**场景 5：先写后读（比如生成临时文件再读）**
```c
FILE *fp = fopen("tmp.txt", "w+");       // 打开就清空，然后写、再 rewind 后读
```

**场景 6：追加 + 需要读回来**
```c
FILE *fp = fopen("log.txt", "a+");
// 读之前必须 fseek 到想读的位置 —— 因为写操作会把光标拉到末尾
```

### ⑤ 带 `+` 模式的致命坑

读写切换必须**刷新或移动文件指针**：

```c
FILE *fp = fopen("t.txt", "w+");
fprintf(fp, "hello");
fseek(fp, 0, SEEK_SET);        // ⚠️ 不 fseek 就读，读不到东西
char buf[16];
fgets(buf, sizeof buf, fp);
```

或：
```c
fflush(fp);        // 把缓冲区写盘
rewind(fp);        // 回到开头
```

原因是 C 标准规定：**在"写"之后、"读"之前（或反之），必须调用 `fflush` 或 `fseek`/`rewind`**，否则是未定义行为。

### ⑥ 加 `b` 的二进制模式

```c
"rb", "wb", "ab", "rb+", "wb+", "ab+"
```
- Windows：文本模式会把 `\n` 转成 `\r\n`，二进制模式不转
- Linux/macOS：两者行为相同，加不加 `b` 效果一样（但写上更规范）

### ⑦ 易错点

- ❌ `fopen("x", "w")` 之后发现原文件内容没了 —— **这是设计行为**
- ❌ `fopen` 不判 NULL 直接 `fprintf` —— `r` 模式文件不存在会崩
- ❌ `a+` 想读文件开头却不 `fseek` —— 光标还在末尾
- ❌ `r+` 写短内容后以为"剩下老数据被删了" —— 实际情况是**老的尾部字符还在**

### ⑧ 推荐的资源管理模板

```c
#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("data.txt", "r");
    if (fp == NULL) { perror("fopen"); return 1; }

    char line[256];
    while (fgets(line, sizeof line, fp) != NULL)
        fputs(line, stdout);

    fclose(fp);        // ⚠️ 别忘了关
    return 0;
}
```

## 第 20 章　`fgets` 安全读行标准模板

### ① 一句话结论

`fgets` 是 C 里最安全的"读一行"函数，但有两个副作用必须处理：

1. **会把回车 `\n` 一起读进数组**
2. **输入超长时，剩下部分残留在输入缓冲区**

标准模板一次把这两个都清掉，还顺便跳过空行。

### ② `fgets` 到底怎么工作

```c
char *fgets(char *s, int n, FILE *stream);
```

- 从 `stream` 读最多 **`n-1`** 个字符，末尾自动补 `\0`
- 遇到 `\n` 就停下，**但 `\n` 会被存进 `s`**
- 读成功返回 `s`；遇到 EOF 或错误返回 `NULL`

对比三种读法：

| | 空格 | 换行 `\n` | 越界风险 |
|---|---|---|---|
| `scanf("%s", s)` | 截断 | 留在缓冲区 | ✅ 有 |
| `gets(s)` | 保留 | 丢弃 | ✅ 有（已废弃） |
| `fgets(s, n, stdin)` | 保留 | **读进数组** | ❌ 无 |

### ③ 标准模板

```c
#include <stdio.h>

#define STLEN 10

int main(void)
{
    char words[STLEN];

    while (fgets(words, STLEN, stdin) != NULL && words[0] != '\n')
    {
        int i = 0;

        /* ① 找停止位置 */
        while (words[i] != '\n' && words[i] != '\0')
            i++;

        /* ② 分支处理 */
        if (words[i] == '\n')
        {
            words[i] = '\0';            /* 短行：把换行删掉 */
        }
        else
        {
            int ch;                      /* 超长行：清空残留 */
            while ((ch = getchar()) != '\n' && ch != EOF)
                ;
        }

        /* ③ 使用 */
        puts(words);
    }
    return 0;
}
```

### ④ 逐段讲清每一句为什么

**外层循环条件**
```c
fgets(words, STLEN, stdin) != NULL && words[0] != '\n'
```
- 第一部分：读失败（EOF / 错误）→ 退出
- 第二部分：`words[0] == '\n'` 说明用户直接敲了回车（空行）→ 不处理
- **空行处理的价值**：避免把空行当作有效数据往下走

**内层 `while` 找停止位置**
```c
while (words[i] != '\n' && words[i] != '\0') i++;
```
只有两种出口：
- `words[i] == '\n'`：**一行完整读进来了**（短行）
- `words[i] == '\0'`：**缓冲区被填满**（超长），后面的字符还留在 stdin

**`if` 分支**
```c
if (words[i] == '\n')
    words[i] = '\0';
```
把 `\n` 换成 `\0` = 把换行删掉。为什么必须删？因为 `puts` 自己会加一个换行，留着 `\n` 就多一个空行。

**`else` 分支**
```c
while ((ch = getchar()) != '\n' && ch != EOF) ;
```
把这一行剩下的字符从 stdin 里**读出来丢掉**，一直读到 `\n`。
- 如果不清空：下一次 `fgets` 会接着读上一行的碎片，当成新的一行 → 逻辑错乱
- 加 `ch != EOF`：防止输入流已结束时死循环

### ⑤ 三种输入的具体推演（`STLEN = 10`）

**① 输入 `hello` 然后回车**

```
fgets 装入：h e l l o \n \0        （7 字节，其中 '\n' 和 '\0' 各 1 个）
i 走：0→1→2→3→4→5，在 '\n' 处停下
if 分支：words[5] = '\0'
puts：打印 hello（自带换行）
```

**② 输入 `abcdefghij123456`（超长）**

```
fgets 装入：a b c d e f g h i \0   （最多 9 个有效字符 + '\0'）
i 走：0→...→9，撞到 '\0' 停下
else 分支：getchar 循环把 j 1 2 3 4 5 6 \n 全部丢掉
puts：打印 abcdefghi
```

**③ 直接回车（空行）**

```
fgets 装入：\n \0
外层条件 words[0] == '\n' → 不进入循环体
```

### ⑥ 一个完整可跑的例子

```c
#include <stdio.h>

#define STLEN 10

int main(void)
{
    char words[STLEN];

    puts("输入多行，空行结束：");
    while (fgets(words, STLEN, stdin) != NULL && words[0] != '\n')
    {
        int i = 0;
        while (words[i] != '\n' && words[i] != '\0')
            i++;

        if (words[i] == '\n')
            words[i] = '\0';
        else
            while (getchar() != '\n')
                continue;

        printf("读到的行：[%s]\n", words);
    }
    puts("结束");
    return 0;
}
```

### ⑦ 易错点

- ❌ 忘了把 `\n` 换成 `\0` → 输出多空一行，而且字符串里带着换行
- ❌ 超长输入不清空 → 下一次读到的都是上一行的碎片
- ❌ `while (getchar() != '\n');` 去掉 `ch != EOF` → 输入结束时空转
- ❌ `fgets` 用 `sizeof(words)-1` 当第二参 → 标准已经帮你算好了，直接传 `sizeof(words)` 即可
- ❌ 以为 `fgets` 会帮你"自动去空格" —— 空格是正常的，不处理（`scanf("%s")` 才截断）

## 第 22 章　考前 5 分钟速查清单

### 【语法】声明怎么读
- [ ] `int *f()` → 指针函数（是函数）
- [ ] `int (*p)()` → 函数指针（是指针）
- [ ] `char *p[5]` → 指针数组（是数组）
- [ ] `char (*p)[5]` → 数组指针（是指针）
- [ ] `int (*f())[10]` → 函数返回数组指针 ✅
- [ ] `int (*f)[]()` → ❌ 非法
- [ ] `int f()[10]` → ❌ 函数不能返回数组
- [ ] `&*q[i]` → ❌ 优先级错，应 `&(*q)[i]`

### 【指针运算】
- [ ] 步长 = `sizeof(指向的类型)`，不是指针自身大小
- [ ] `q+1`（`char (*)[6]`）→ +6；`(*q)+1` → +1
- [ ] `arr` 与 `&arr` 数值可能相同，类型不同
- [ ] 函数指针不能做 `+1`

### 【生命周期】
- [ ] 局部变量 / 局部数组 → 栈 → 不能返回地址
- [ ] `static` 局部 → 静态区 → 可返回，但只有一份
- [ ] `malloc` → 堆 → 可返回，必须 free
- [ ] 字符串字面量 → `.rodata` → 只读
- [ ] 函数指令 → `.text` → 函数指针存的是这里的地址
- [ ] 栈"回收"不等于清理数据，只是指针回退

### 【字符串】
- [ ] 字符串 = 以 `'\0'`（数值 0）结尾的 char 数组
- [ ] `'\0'` ≠ `'0'`（0 vs 48）
- [ ] 部分初始化时剩余元素零初始化
- [ ] `sizeof` 含 `\0`，`strlen` 不含
- [ ] `char arr[] = "abc"` → 栈副本，可改
- [ ] `char *p = "abc"` → 指向 rodata，不可改

### 【数组传参】
- [ ] 数组名退化为首元素指针
- [ ] `f(int a[])` ≡ `f(int *a)`
- [ ] 函数内 `sizeof(a)` = 8
- [ ] `arr++` 只改副本
- [ ] 必须额外传 size

### 【函数指针】
- [ ] `f == &f == *f`（函数范围恒等）
- [ ] `fn` = 入口地址；`&fn` = 指针变量在栈上的地址
- [ ] `fn(x,y)` ≡ `(*fn)(x,y)`
- [ ] 真实用途：回调、表驱动、运行时切换

### 【内存模型】
